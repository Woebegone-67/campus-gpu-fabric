# 单次普通续租剖析

这次测量定位了明确的固定库存成本，不是新的正式性能验收。

- 只剖析一次 `allocation.renew`；准备租约、释放租约在剖析区间外。保留全部历史。
- 来源：探针报告给出的临时数据库，128 个库存节点。生产源码未修改，现有服务未停止。
- 构建源码摘要：`3a99d174691d76d2ffa28bdf38f696e0b404c4d295e10d0c60d7a4f672cdb681`；测量前后摘要一致。
- cProfile 总计 446,804 次调用、159.753 ms。此时间包含 profiler 开销，且宿主机同时运行完整测试和旧 CPU 服务；不能与之前 61 ms 的探针中位数直接比较。

## 归因

| 路径 | 调用或占比 | 判断 |
|---|---:|---|
| `materialize` | 19,426 次，累计 125.025 ms，占 78.3% | 主要剩余成本 |
| `changed_units` | 65.671 ms | 比较触及对象时重新转换和编码 |
| `rebase` | 64.829 ms | 再次对同一缓存转换和编码 |
| 固定库存模型转换 | 128 次 NodeInventory、1 次 Placement | 仍验证完整库存；Pydantic JSON 验证合计约 4.30 ms |
| 库存推导 | 1 次，累计约 20.64 ms | 次于数据转换成本 |
| 实际持久化 | 6 个变化单元、3 个实体行 | 读取/转换量远大于实际变化量 |

`materialize` 直接触发 16,038 次 JSON primitive 编码后解码。库存节点本身含 7,936 个叶值；每个节点在变化比较与 rebase 中各转换一次，因而可由缓存数和循环推算出 15,872 次节点叶值往返，占这类往返的 99.0%。128 节点在这两个阶段合计整实体编码 256 次。后两项是基于实测缓存数和当前循环的精确推算，不是另跑一轮测量。

这些累计时间存在调用包含关系，不能把 `materialize` 与两阶段时间相加。两阶段本身顺序执行，合计约 130.50 ms。

## 有证据支持的下一步

1. JSON 不可变标量直接复用，保留数值有限性与不受支持类型检查，取消逐 primitive 编码/解码。
2. rebase 复用本次比较已经得到的规范 JSON，只更新必要的基线，避免第二遍编码 128 个未变化节点。

本报告不支持降低资源守恒校验、丢弃历史、改弱隔离或增加跨事务可变缓存。完成以上两处后，先跑针对性存储、CPU、并发与 HTTP 回归，再决定是否需要进一步测量；不据此宣称 CP4 已通过。

原始产物：`renew.prof`、`result.json`、`exclusive-top15.txt`、`inclusive-top15.txt`、`attribution-summary.json`；可复现脚本 `run.py`。
