# CP1 联合验收与 CP2 准入结论

日期：2026-11-14。审查对象：合并双方交付的 `main@9bb0bb5`。
验收分支：`review/cp1-acceptance`。本分支只增加验收程序、回归测试、CI 和交接说明，生产 `src/`、前端 `web/`、契约与配置均未改变。

**技术联调通过；正式 CP1 尚未通过，暂不进入 CP2。** 用户已确认两位成员只提交了代码、尚未交叉操作。剩余人工门槛明确，不能用一个 AI 切换 Alice/Bob 身份代替。不需要重做后端，也不要求提前实现 CP2 的恢复与真实执行。

## 已执行的技术验收

| 内容 | 实际结果及范围 |
|---|---|
| 完整自动化测试 | 278 项 Python 测试通过；包括新增 10 项工作流挑战及 5 项真实 TCP 查询安全测试 |
| 工程入口 | 契约生成一致性、Ruff、前端构建、CP0 五项真实进程冒烟通过；客户端传输测试 9 项通过 |
| A 内核 TCP 验收 | 10 项通过：32 请求竞争、32 次同幂等键、冲突、隔离、租约、响应丢失、SIGKILL 重启、失败后结算 |
| A+B 集成 TCP 验收 | 7 项通过：真实后台编排、32 并发、响应丢失与硬重启、查询隔离、失败保留/释放、终态自动释放、过期阶段安全重试 |
| 资源边界 | CPU、内存、GPU 数量、显存/profile 不匹配不会获配；有效切片占用后整卡不能再次分配 |
| 策略接线 | builtin、B0、B1、B2 的排队、资源交接、重启与阶段幂等测试通过；不据此声称策略收益 |
| 实际浏览器 | 六工作区读取；提交→运行→管理员推进10秒→成功及租约释放；刷新重新认证后同一工作仍在；Bob访问Alice工作返回404 |
| 部分成功界面 | 已获租约、任务未创建时，故意使页面版本落后；创建返回409。刷新重试使用原租约，仅一个任务/attempt。随后取消显示Cancelled，keep_lease仍为Allocated，释放入口可见 |

测试项有交叉覆盖，不能将数量相加解释成独立场景数。数据均来自隔离实例，未重置任何成员的工作实例。

部分成功试验通过 `accept_cp1_joint:manual_app` 暂停后台 worker，构造可重复的阶段竞争；其余集成 TCP 场景使用正式 B 入口并启用 worker。测试工厂不改变生产模式。UI 部分失败是版本冲突，并非已实现任意故障注入。

浏览器取消确认曾遇到自动化工具超时，之后通过正常键盘确认并观察到取消成功；后续手动释放确认未能被工具可靠处理，**未计为 UI 释放通过**。HTTP 层的显式释放及重复释放已通过。双人清单应实际点击验证这一步。

## 门槛与证据位置

`configs/checkpoints.json` 的七项门槛保持不变。`tests/acceptance/cp1/cp1_*.py` 现均有可执行入口，机器项运行真实断言；UI项检查实际观察材料，缺少或过期即失败。

- `evidence/cp1/a_core_receipt.json`、`a_core_http_history.json`：A 后端运行。
- `evidence/cp1/joint_backend_receipt.json`、`joint_backend_history.json`：A+B 运行及进程历史。
- `evidence/cp1/joint/`：构建日志、浏览器快照、截图、部分成功的真实 HTTP 状态与 UI 观察说明。
- `evidence/cp1/joint/final_validation.json`：本轮最终命令退出码、时间和构建身份。
- [门槛独立审查](CP1_GATE_AUDIT.md)：合并提交在本轮补齐验收入口前的状态，及审查边界。

观察截图沿用同一生产代码；本轮后续增加的文件只有验收与文档。UI记录须披露这个来源关系，不能声称重新运行了两个真人。验收材料本地生成，CI另提供Linux运行的工件；凭据、数据库和测试密钥不提交。

## 进入 CP2 前还需什么

1. A、B 在已审查版本各自完成[短交接清单](CP1_HUMAN_HANDOFF.md)，保留工作ID和去敏感的实际观察记录。尤其核对取消后租约的保留/释放及刷新状态。
2. 汇入两人真实记录，运行 `cp1_normal_journey.py`；检查本轮其余证据仍对应当前构建，再生成七项齐全的 `evidence/cp1/receipt.json`，运行 `make checkpoint CP=CP1`。

当前没有生成顶层 MET 回执。验收页也仍诚实显示 NOT_RUN。它的读取器目前未连接完整联合回执；后续应接入有效构建匹配，不能直接把标签改成通过。

## 后续界面协调事项

- 503 目前统一显示“能力等待后端接入”，应在 CP2 的故障体验中区分暂时不可用与尚未实现。
- 如果以后持久化 rejected stage，要重新协调“同阶段未知回执重试”与“失败后的新阶段”。当前内核不持久化 rejected stage，本轮未发现该项导致死锁。
- 当前10秒逻辑模型不执行镜像或命令；真实CPU、保存/回收/恢复和CP2的全部API不在此次通过范围内。

本轮停在 CP1 收口，未开展 CP2 开发。
