## 1. 产品目标与设计判断

织算服务于校园内临时、可撤回的算力共享。使用者需要完成工作，贡献者需要保留设备控制权，管理员需要处理异常。用户进入界面后，应能判断工作和设备当前处境，并完成对应操作。

这版设计主要解决四个问题：

1. 把当前最需要处理的事情放到前面，减少逐个工作区查状态的负担。
2. 用同一项工作的详情贯穿提交、等待、中断、接续、结果和资源归还。
3. 保留品牌辨识度，同时让高频读写区域安静、清楚、稳定。
4. 让艺术总览和操作工作台形成连续体验，切换不会重置用户正在做的事情。

当前评分依据为仓库 [challenge.md](../../spec/official/challenge.md) 的 55/45。视觉设计服务于可操作性与实际价值；不改变接口、资源账本、权限和证据要求。CP4 未通过的规模、延迟和真人交付项不因界面更新而变成通过。

## 2. 去除上一版的模板感

### 2.1 上一版具体问题

“你的工作停在哪里”“信息范围”“同一对象”“尚未开始，不显示成功”等设计者说明占据了产品主区域。标题、徽章、正文、流程图又重复表达同一状态。相同大小的容器使真正重要的工作和辅助解释拥有相同视觉重量，整齐但缺乏取舍。

B 的黑色点阵方向可以保留为视觉资产；全页星点穿透输入框、半透明表格和错误提示的形式需要调整。浅色、圆角或删掉背景都不会自动解决内容组织问题。

### 2.2 本版执行原则

| 原有表达或习惯 | 本版处理 |
|---|---|
| 抽象问句作为大标题 | 显示具体工作、设备或简短页面名 |
| 每段说明都放进卡片 | 根据内容用列表、分组、表格或留白；有独立交互边界时才用容器 |
| 重复状态标签 | 一个主要状态；只补充对下一步有帮助的原因和后果 |
| 开发者自证文案 | 放到帮助、技术详情或验收材料；正文直接说明事实 |
| 长 UUID、revision、逻辑秒占主位 | 工作名称优先；完整身份和原始时间在详情可查、可复制 |
| 大面积数字填版 | 只展示有来源、能帮助当前决定的数据；允许画面安静 |
| 所有任务变成漂浮粒子 | 任务始终有可读名称、状态和稳定位置；艺术形态作为补充 |
| 每次进入都播放开场 | 返回已用过的空间，保留工作上下文；不强制播放 |

界面需要“完成操作的人”的语言。例如“已保存进度，等待可用资源”；无需在主界面解释“报告不等于核验不等于接续”的系统论证。具体详情仍须准确区分这些事实。

## 3. 同一平台中的用户与权限

借用和贡献是同一个人可能同时进行的活动。个人总览应能汇集本人工作的变化及本人设备的事项，不要求登录后先选择三张互斥角色名片。

| 身份与活动 | 默认内容 | 可用工作入口 | 数据边界 |
|---|---|---|---|
| 使用算力的人 | 本人工作、必要处理、最近结果 | 我的工作、工作详情 | 后端授权的本人对象 |
| 贡献设备的人 | 本人设备占用、收回进度、归还结果 | 我的设备、设备详情 | 本人资源及履职必需信息，不扩展为借用者文件访问权 |
| 同时借用与贡献 | 合并相关事项，按重要性排序 | 我的工作、我的设备 | 两组对象分别按授权读取 |
| 管理员 | 管理范围内的异常与运行入口，也可保留个人活动 | 管理入口中的运行、资源、审计、实验和验收 | 后端认可的管理授权；不从 profile 名称推导权限 |

当前基线没有可信的 `session/me` 能力投影。产品方向不能被实现为“选择 admin 标签就获得管理视图”。沿用现有身份验证行为；需要新的能力查询时，由 A/B 先确认扩展契约。管理入口可有开发期可见提示，但每次请求仍由服务端授权，拒绝时不能展示残留管理数据。

此外，当前 `AuthenticatedActor.role` 仍是 researcher/contributor/administrator 单值，研究者工作流与贡献操作分别校验角色。上表是目标体验，当前普通凭据尚不能据此获得两类能力。用户已明确要求解除这种僵硬切割：本次文档推送后，A 开始独立后端修改，将使用与贡献能力兼容到同一账户，管理能力独立。B 的视觉和视图可以并行推进，真实双能力联调须等待新授权投影和服务端动作校验完成；不要把普通用户升级为管理员来临时绕过限制。

身份文件与 bearer 仍只在现有浏览器内存范围使用，不写入页面地址、浏览器持久存储、日志或录屏。刷新后重新导入身份是现阶段真实能力，不能设计成已经存在的持久登录。

## 4. 两个空间的职责

| 总览 | 工作台 |
|---|---|
| 快速判断目前是否需要介入 | 持续查看、创建、配置和处理 |
| 重要事项、当前工作、本人设备、最近结果 | 工作列表与详情、设备管理、按权限进入管理工具 |
| 内容经过选择与聚合 | 能找到完整且有边界的数据 |
| 可有克制的艺术场景 | 稳定、不透明、可高效读写的业务表面 |
| 允许长驻、空闲时安静 | 允许直达、返回后继续操作 |

这两个空间不是一次性的步骤向导。用户可以直接进入工作台并长期停留。首页深链接中的任务、已有工作地址、刷新后返回都不强制绕行总览。

页内最多一个“当前空间”状态。工作台内部的任务、资源、详情仍可以拥有各自地址；不能为了坚持“只有两页”而把所有功能堆成一个无限长屏幕。

## 5. 共用外壳与导航

### 5.1 两页保持的元素

- 左上角品牌标识“织算”，尺寸克制，不增加重复英文栏目口号。
- 可见的“总览 / 工作台”切换器。当前空间有文字和形状上的选中状态，不能只用两个无标签圆点。
- 当前身份入口、连接状态；状态的技术细节折叠。
- 需要处理的事项数量或入口，数量必须来自已经加载且有权读取的范围。
- 进入工作台后的局部工具导航，不必在总览展开全部管理菜单。

顶部功能排列建议为：品牌在左，空间切换在稳定位置，身份与服务状态在右。不能让头像、粒子按钮、主题切换、声音开关同时争抢主要导航位置。

### 5.2 切换路径

| 触发 | 目标 |
|---|---|
| 总览的“工作台”入口或合格的向左手势 | 上次使用的工作台子页面；首次则为我的工作 |
| 总览点击工作 | 对应工作详情，保持同一对象身份 |
| 总览点击设备或收回事项 | 对应设备/收回详情 |
| 工作台的“总览”入口或合格的向右手势 | 更新后的总览；保留工作台筛选、滚动和草稿 |
| 浏览器后退/前进 | 遵循页面历史，不重新提交操作，不跳过身份检查 |
| 直接打开旧工作链接 | 定位原工作，不先播放首页 |

手势与点击只改变视图。任何切页、动画结束、页面重新挂载都不能触发登记、取消、收回、释放或恢复请求。

## 6. 总览的内容优先级

### 6.1 需要处理

只包括有实际用户动作、明确后果或迫近时限的事项，例如登记结果不确定需要查询、任务失败后可采取的合法动作、可恢复且确需用户发起恢复、贡献者收回尚未完成而需要进一步处理。

是否需要用户介入必须来自状态和可用动作。已保存并在正常等待兼容资源的工作，可以显示进展，但不应自动变成红色警报。未实现的自动恢复不能被文案默认承诺。

多条事项以严重性、真实截止、发生时间和稳定对象 ID 排序。同一工作的一串事件合并成一个当前事项，不把 received、verified、applied 各做一个通知轰炸用户。已解决事项退出待处理区域，重要结果可短暂进入最近变化。

### 6.2 正在进行的工作

展示可识别名称、主要状态、与当前状态相关的一条辅助信息，以及进入详情的入口。

- 有可信完成量和总量时才展示百分比，并注明其范围。
- 无总量时显示当前阶段或最近一次进展；不用等待时间推算假进度。
- 不能用超时值充当预计完成时长。
- 逻辑模拟的时间不能伪装为现实训练时间。
- 任务暂停后不继续播放“正在计算”的动效。
- 多工作时采用稳定列表，允许展开全部；不让每次刷新都重新随机排列。

### 6.3 本人设备

拥有贡献资源的用户显示设备简要占用和正在进行的收回。没有设备时不为对称留一大块空卡片；可在工作台提供贡献入口。查看占用不等于能查看借用者文件。

### 6.4 最近结果与变化

优先展示可领取结果、明确失败或收回完成等对用户有用的变化。底层心跳、revision 增加、重复轮询不进入通知。非动作型提示可“已读”，真实未解决事项不能因已读而被视为已解决。

### 6.5 首版数据范围

当前接口以分页快照为主，总览不能假装具备尚未实现的全量通知中心。如果只汇集已加载对象，明确“当前已加载工作”，不要写“全部正常”。跨页总数、完整待处理排序、服务端已读状态或跨设备同步需要真实投影支持；缺失时在数据映射中标为待接入。

## 7. 总览构图与内容密度

在 1440×900 参考桌面上，主内容应在第一视口内呈现最重要事项与主要工作；更长列表可以正常纵向滚动。空间切换不占整个屏幕的三分之一。下面是信息关系图，不是要求照抄的卡片布局。

```text
织算                  总览  工作台                     身份 / 服务状态

需要处理的一件事（有则出现，文字和操作保持稳定）

当前工作                                      克制的艺术区域
实际任务名称   当前状态   必要进展              对应当前工作的关联表达
实际任务名称   当前状态   必要进展              不承担唯一信息表达

本人设备的相关变化（拥有设备时）                最近结果 / 最近变化
```

关键内容区可以占页面较大比重，艺术区域只在内容允许时展开。不要强制左右各占一半，也不要把每一行都做成独立悬浮玻璃卡。

建议起点：桌面内容左右留白 32–48px，内容最大宽度约 1440px；工作名称 18–24px，正文 14–16px。这些是排版试稿值，需用长中文名称、英文文件名和多任务密集状态检查。最终仍以可读性和第一视口主任务完整为准。

空闲首页可以只保留“目前没有需要处理的事项”、最近工作与开始工作的入口。首次无工作时展示当前实例支持的任务类型和一个开始按钮，不模拟任务填充艺术图景。

## 8. 艺术表达与品牌语言

### 8.1 视觉主题

保留 B 已有点阵的识别潜力，把“织”落到连接与延续：工作可以换资源，已有进度仍有来源。建议使用少量可辨认的线、节点或空间层次，表达选中工作与资源/保存进度的关系。

这是视觉方向，不要求逐个数据库实体变成节点。无法诚实映射的数据不进入图景；纯装饰可存在，但不能用“实时 GPU 网络”“全校算力运行”等标题让人误解。

### 8.2 层次

1. 文字与主要操作层：始终清楚、固定可读，不随鼠标漂移。
2. 工作相关视觉层：可表达选中、运行、暂停或关系变化，有对应文字。
3. 环境装饰层：低对比、低运动，退至内容背后或侧面；不穿透表单与正文表面。

艺术层不拦截常规点击、不截获文字选择、不夺走键盘焦点。若用户能点击艺术中的任务，对应普通列表也能打开同一对象；无需掌握图例才能完成工作。

### 8.3 动效纪律

- 状态发生真实变化时才有一次克制反馈，不把每次轮询成功都播放成新事件。
- 后台标签页或艺术层不可见时停止无用渲染；降低动效后停止持续移动。
- 无资源、服务断线和数据过期时，不继续暗示运行繁忙。
- 工作台隐藏艺术层后，不能只设透明度为零却持续消耗绘制资源。
- 不采用全文闪烁、持续呼吸的红色警报或随鼠标剧烈变形的业务区。

## 9. 工作台的信息架构

普通用户主要入口为“我的工作”“我的设备”；管理工具按授权显示。无需保留原六区在主导航中的同等权重，但必须保留其真实能力和历史链接。

```text
工作台
├─ 我的工作：列表 / 新建 / 工作详情
│  └─ 工作详情：当前情况 / 执行与接续 / 结果 / 关联记录
├─ 我的设备：资源列表 / 设备详情 / 贡献与收回
└─ 管理：运行与异常 / 资源 / 决策与事件 / 实验报告 / 系统验收
```

列表、详情、表单使用适合内容的密度；不要把总览的大幅艺术构图复制到第二页。工具区允许表格、紧凑筛选和局部详情面板，表面不透明。原始 JSON、版本号、请求号放到技术详情或可复制区域。

## 10. 我的工作列表

默认优先显示本人未结束工作，保留查看全部和按状态筛选的方式。建议列为：工作名称/短 ID、状态、必要原因、最近变化、下一操作。列数应根据实际字段裁剪，不填未经后端提供的百分比、费用或预计完成时间。

- 行本身可打开详情；行内操作与整行点击有明确边界。
- 一行不堆满取消、恢复、续租、释放、重试等按钮。最相关操作直接显示，其他合法操作放入菜单或详情。
- 刷新保持筛选、选中对象和合理的滚动位置；更新失败不把旧列表换成空列表。
- 分页结果与总览的当前加载范围明确；未加载的数据不能被前端搜索描述为全库搜索。
- 昵称或工作名称若未有可持久字段，使用真实短 ID 和已有任务描述作为临时标题；不宣称支持跨设备命名。

## 11. 工作详情

### 11.1 顶部

工作名称、一个主要状态、当前关键原因和一个主要操作。次要信息为运行模式、最近更新时间和短 ID。长 UUID 可复制并可查看完整值。

用户在这里要能连续回答：现在怎么样、为什么、下一步能做什么、结果与资源去了哪里。工作状态、执行状态、租约状态不同，不应压成一个模糊“成功”徽章。

### 11.2 执行与接续

平时显示简洁过程。只有发生中断时，展开有意义的连续性信息：

| 真实事实 | 普通文案 | 详情中可核对 |
|---|---|---|
| 收回请求已接受 | 设备正在收回 | 通知时间、截止、相关设备 |
| 收到保存报告 | 收到保存报告 | 报告状态及来源代次；未核验时不说可恢复 |
| 工件核验通过 | 保存点可用 | 核验记录和可用范围 |
| 旧执行停止被确认 | 原执行已停止 | 实际确认；资源状态另行展示 |
| 等待兼容资源 | 等待可用资源 | 已知等待原因和可用动作 |
| 新代次实际使用工件 | 已从保存点继续 | 新执行、工件关联及记录 |
| 工件无效或保存失败 | 本次进度未能保存 | 失败原因、合法的重启/取消等选择 |

状态不能由动画的播放进度决定。用户离开页面时，工作仍由后端运行；回到页面重新读取真实状态。

### 11.3 结果与资源

结果文件及下载在可获得时直接呈现。结果正确下载和租约释放是独立事实：工作结束但仍持有租约时，显示归还状态和允许的操作。失败也需要说明资源去向。

下载经过原授权与完整性校验，保留原始 JSON 字节及大整数精度；不把浏览器重编码后的对象冒充原始结果。文件名应对应实际工件；无工件的逻辑模拟不出现虚假下载入口。

### 11.4 关联记录

事件和决定作为同一工作内的次级信息，按需展开。保留当时快照、计划与实际执行差别；不可从当前状态补写过去的理由。更多底层字段进入技术详情，不常驻首页。

## 12. 新建工作

第一屏先明确当前实例支持什么，再收集必需输入。当前两种模式为逻辑模拟、固定 CPU 参考执行，均不执行用户填写的 image/command/env，GPU 库存仍模拟。

建议结构：支持的任务/运行方式说明 → 必需资源与租约 → 中断与结算选择 → 提交。MIG、预算、重试、可选超时等高级信息按需展开。模式来自服务端，不虚构用户可自由切换后端模式的选择器。

若 image/command 必须作为登记元数据保留，应明确其用途并收进高级信息；不在普通入口使用会运行任意 train.py 的暗示。不能通过本轮 UI 改造偷偷开放任意 shell 执行。

输入错误就近提示并保留内容。提交期间禁用重复提交。响应不确定时保留原工作 ID 和相同输入，先查或重试同一登记；不能换 ID 另起一项。租约已分配但任务创建失败时，进入同一工作详情处理已有租约。

双页切换保留当前会话中的草稿，不触发提交，也不把草稿写入携带凭据的浏览器存储。刷新可能丢失未提交输入，应在真实需要时提示；不能为实现手势先引入跨身份共享草稿。

## 13. 我的设备与收回

展示本人设备的名称/真实 ID、已声明能力、当前占用和共享状态。当前贡献登记是模拟库存声明，不能写成“已检测并接入你的显卡”。

收回过程在设备详情内连续呈现：确认范围与通知参数 → 请求已接受 → 等待执行停止 → 资源状态更新。接口成功回执不等于物理停止确认。若停止未确认或资源被隔离，保留相应状态，不展示“可以安全使用”。

收回属于有后果的业务操作，需要清楚的对象与影响提示。双指、拖拽、切页和艺术节点误触都不能直接完成收回。提交后的反馈附着在同一设备记录，避免只显示短暂 toast 后失去结果。

## 14. 管理工具

管理入口继续支持运行与异常、资源、决定/事件、隔离实验、报告和验收。把它们组织为管理工具，不让普通研究者承受完整运维导航。

- 异常汇总只有在数据范围和投影支持时才显示全局计数。
- 决策解释能追到当时输入、候选边界和实际提交；搜索截断不能写成全局不可行。
- 隔离实验与运营实例明确分开，不在普通用户流程暴露测试入口或测试 Key。
- 报告显示原实验构建及历史标识，保留 R=1.00 和不利结果。
- 系统验收按真实回执呈现未测、未达和通过；不造一个将所有状态概括为绿色的健康评分。
- 管理员操作也应保留工作台上下文，不能切页就重跑实验。

## 15. 双指切换与转场

### 15.1 体验目标

在已验证的桌面触控板环境中，从总览向左滑进入工作台，向右滑返回。用户能感受到两个相邻空间；滑动过程中，艺术层逐渐退去，业务表面接替它。详细识别规则以 [专项详规](UI_GESTURE_AND_MOTION.md) 为准。

网页只能基于横向输入事件判断意图，不能可靠识别两根手指。系统/浏览器手势可能抢先处理。因此可见切换器始终可用；发生原生导航冲突的环境必须停用冲突手势，不能要求用户修改系统设置才能使用产品。

### 15.2 触发范围

总览的非交互画布/留白可作为起手区域；工作台保留可辨认的页首非交互切换区域。输入框、选择器、按钮、已选择文本、表格与代码横滚、弹窗、拖动操作和缩放手势不参与空间切换。不得在整页全局捕获所有 wheel 并阻止滚动。

### 15.3 过渡内容

切换期间保持品牌、空间位置和当前工作线索。点击特定工作进入时，目标详情选中该工作；普通滑动进入时恢复上次工作台。艺术层降低存在感，正文清晰可读；不要把正在阅读的文字同时缩小、旋转或模糊。

每段手势最多切换一次；惯性尾部不能触发反向或第二次跳转。未达到确认条件时回到原页，不留下半页停驻。新服务状态可以更新数据，但不自动驱动横向跳页。减少动效时使用直接切换或极轻过渡，功能保持完整。

## 16. 状态、异常与通知文案

| 情形 | 用户可见表达 | 行为 |
|---|---|---|
| 无数据且请求成功 | 暂无工作 / 暂无设备 | 给一个与权限相符的开始入口 |
| 首次加载 | 正在读取当前工作 | 保持布局，不画虚假进度 |
| 有旧数据，刷新失败 | 更新失败，显示上次读取结果 | 保留旧内容和时间，允许重试 |
| API 返回非 JSON | 暂时无法连接服务 | 技术详情说明代理/响应情况；不直接断言根因 |
| 身份失效 | 身份验证失败，请重新应用身份 | 保留可安全保留的本地草稿，不展示旧身份数据 |
| 无权限或对象不可见 | 当前身份无法查看这项内容 | 遵循404/403语义，不泄露对象是否属于他人 |
| 提交结果未知 | 尚未确认提交结果 | 保留原ID，查询或重试同一登记 |
| 已分配但未创建任务 | 资源已分配，任务尚未创建 | 按legal_actions处理重试/归还 |
| 正常资源等待 | 等待可用资源 | 不持续红色报警、不承诺无依据ETA |
| 保存失败 | 本次进度未能保存 | 显示原因及实际允许动作 |
| 工作结束、租约仍占用 | 工作已结束，资源尚未归还 | 处理结算选择；不将结束等同于释放 |

技术细节可包含请求 ID、错误码、原始响应，但放在用户主动展开的位置。HTTP码不替代普通解释，普通解释也不能改写真实业务拒绝。

## 17. 视觉系统建议

### 17.1 颜色与表面

首版可沿 B 的暗色品牌方向，采用偏墨色的环境、稳定的深色工作表面和一种克制的青绿强调色。浅色方案作为同一系统的变体，不在转场时强制由纯黑跳到纯白。

建议起点色值只用于设计试稿：暗背景 `#11191B`、工作表面 `#1B2528`、主文字 `#E8EFEE`、次文字 `#A7B8B9`、强调色 `#76C5B3`；浅背景 `#F3F5F4`、工作表面 `#FFFFFF`、主文字 `#243537`、次文字 `#58696B`、强调色 `#1F7166`。B 应检查实际字号、状态色和透明叠加后的对比度，不能将这些色值当作已经通过可读性测试。

状态采用文字+图标/形状，颜色为辅助。成功、等待、失败颜色保持一致，不为每张普通卡分配不同渐变。正文后无高频点阵，表单不使用透出运动背景的玻璃效果。

### 17.2 字体与层级

中文与英文采用系统无衬线作为初始基线，长数字/ID在技术详情使用等宽。B 可替换为有授权、跨平台可用的品牌字体，但不可让字体下载失败破坏布局。

建议桌面字号：空间标题 26–32px，主要对象名称 18–24px，正文/表格 14–16px，辅助标签 12–13px。全局大字标题只在有必要时出现；不得把多个区域都设为同一级的大标题。时间、单位与数字靠近，不用极淡灰色隐藏重要状态。

### 17.3 间距与容器

采用 4/8px 基础节奏，区域间距约 24–40px，行内约 8–12px。列表行可从 48–56px 高度试稿，密集状态按内容调整。圆角以 6–10px 为主，弹层可略大；避免所有矩形都成为大药丸。

容器应对应独立操作或信息范围；普通说明段落用文本和留白。必要表格使用行分隔，尽量少用纵向网格。艺术画布和业务表面边界清楚，不以大量投影营造层级。

## 18. 响应式与无障碍

桌面重点检查 1440×900，同时检查 1280×800 和 1024 宽度。窄屏检查 390px 与 320px：总览改为单列，艺术区域收缩或省略；工作台将关键列转为可读记录，必要横滚只发生在有明确边界的表格/代码内。

空间切换器在所有尺寸可见。手机不要求双指动作；使用可见入口，触屏增强另行验证，不从桌面wheel实现自动推断支持。

所有核心操作可用键盘完成。切页后焦点转到合理页面标题/选中对象，返回后可恢复入口焦点；不能把焦点留在不可见的旧页按钮上。模态框保留焦点约束，关闭后返回触发点。

减少动效偏好关闭持续移动及大幅位移，保留状态文字。动态通知仅播报真正重要变化，不把每次轮询都送入屏幕阅读器。图景中的关键信息有普通文本对应。

初版目标采用正文至少4.5:1、较大文字至少3:1的对比度检查，焦点与交互边界清晰可辨；完整无障碍合规须另行审查，不因满足少量数值就宣称全面达标。

## 19. 状态保存与更新

需区分服务端事实、页面状态和未提交输入。服务端事实只从授权响应读取；页面状态包括当前空间、筛选、滚动、选中对象；草稿包括尚未提交的资源配置。

同一会话内切页保留页面状态和草稿。身份改变时取消旧请求，清空旧身份对象、工件、错误和跨对象选择；不能为了连续转场短暂展示另一人的工作。新响应需匹配当前身份与请求版本。

新增总览不应为每个小组件独立高频拉取同一快照。共享已有读取结果或采用经过确认的投影，按可见性、有无活动工作和用户刷新决定更新。当前后端存在响应瓶颈，UI不得以更密集轮询掩盖它。

两页使用同一事实来源。切换可见性不暂停后端业务，不依赖页面挂载继续自动结算。部分数据错误可以局部显示，但不能把组合不完整的快照说成全局正常。

## 20. 路由与兼容

新路由命名可由 B 结合现有 hash router 决定。推荐将“空间”和“对象”分开表达，例如总览一个入口、工作台下有工作/设备/管理子路由。不要在文档未接线时宣称这些示例路径已可访问。

现有 `#continuity?intent=...` 等链接必须继续能定位对象，或通过兼容跳转进入新详情。浏览器后退/前进要可预期，手势不能制造每一帧一个历史条目。一次确认切换最多写入一个导航状态；取消手势不写入。

深链接中不放 bearer、身份文件内容或大段表单输入。工作ID仍按后端权限访问；知道URL不等于获得权限。

## 21. B 需要交付的设计状态

每个页面都要有真实内容形态，不只画全绿的成功状态。以下是设计清单，初始均待设计/待验证：

| 编号 | 页面状态 | 重点 |
|---|---|---|
| O1 | 总览，工作正常运行 | 进展可读，艺术层不干扰 |
| O2 | 总览，需要用户处理 | 单个优先事项清楚，动作有依据 |
| O3 | 总览，自动等待接续 | 与必须处理区别，不假报警 |
| O4 | 总览，同时借用和贡献 | 合并关注，不要求互斥角色选择 |
| O5 | 总览，空闲/首次使用 | 无伪数据，有合理起步入口 |
| O6 | 总览，断线/旧数据 | 清楚说明更新时间与不完整范围 |
| W1 | 工作列表，多个状态和长名称 | 密度、筛选、分页、选中明确 |
| W2 | 新建工作，必填与高级项 | 实例能力清楚，输入错误保留内容 |
| W3 | 工作详情，已分配但创建失败 | 正确处理原租约，无重复提交 |
| W4 | 工作详情，保存/停止/接续 | 三种保存事实与资源去向准确 |
| W5 | 工作详情，完成或失败 | 结果、下载、结算分别明确 |
| D1 | 设备详情，收回进行中 | 回执、停止确认和归还不混淆 |
| M1 | 管理，报告与验收未达 | 负结果、历史构建和未测可读 |
| T1 | 两页切换、途中取消和返回 | 连续对象、输入保留、无误提交 |
| A1 | 窄屏、键盘、减少动效 | 核心流程完整可达 |

这些编号是设计检查用，不能替代原 CP4 W2 失败场景或其他既有测试编号。

## 22. 实施顺序与验收

第一步完成普通用户同时借用和贡献的总览/工作台静态结构，用合法示例数据检查内容密度；示例清楚标明且不得进入实际验收。

第二步接入现有真实查询、动作和路由，完成空态、错误、部分成功、身份切换、下载以及当前CPU模式说明。此时即使关闭所有动效，也应能独立完成全部主要任务。

第三步增加转场与限定区域手势。先通过方向、边界、惯性、嵌套滚动、输入保留的定向检查，再在真实Safari/Chrome触控板上校准；浏览器冲突无法解决时降级并记录。

第四步检查视觉细节：长中文/英文、表格密度、焦点、窄屏、减少动效、慢响应；移除重复提示和没有信息价值的容器。最后才细化艺术场景，而非先以高成本背景锁死布局。

每次提交只跑受影响检查。文档更新不重跑125次策略实验；手势和视图状态改动要有对应交互测试；最终合并候选再做一次必要完整工程检查与真人三方活动链。代码通过测试不代替实际双指设备操作，代理切换身份不代替B真人验收。

通过标准包括：用户不用解释能找到需要处理的事项；两页切换不丢草稿/选择、不引起业务写入；同一工作在中断后仍能找到并理解下一步；资源归还与任务完成没有误导；无权限残留；实际下载正确；关闭动效后同样可完成工作。

## 23. 明确不在本轮界面范围内的承诺

通用GPU训练、任意镜像执行、贡献收益金额、全校实时资源地图、可靠ETA、通知跨设备同步、可信角色会话接口以及新调度收益，均不能由 UI 擅自宣称已实现。若 B 希望纳入，先列数据和服务依赖，再按边界交给 A/B 协同实现。

B 可自由深化品牌字形、点阵的具体美术、层次与配色，也可用真实可用性证据调整布局。本说明不要求复刻旧浅色草图；那份草图仅用于前期结构讨论，其视觉方向已被用户否定。
