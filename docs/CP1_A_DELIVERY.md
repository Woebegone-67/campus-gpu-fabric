# CP1 A 后端交付记录

交付版本：0.2.0，阶段停在 CP1。CP0 已完成，A 的正常执行链可交接；联合 CP1 尚待 B 的产品集成和双人操作，不进入 CP2。

## 本轮完成

SQLite 串行事务提交资源 claims、事件、阶段绑定和原始 HTTP 回执。库存从有效 claims 派生，避免另设可漂移的 free 计数。单节点 CPU/内存/存储、GPU 型号/显存/profile/标签均重验，整卡和切片互斥。

正常链支持申请/排队、租约续期与归还、任务开始/成功/超时/取消、三种显式结算策略、逻辑时钟所有截止边界、重启重载与租户隔离。WorkIntent 绑定与 stage 回执原子保存；成功阶段重复请求先复用历史结果。公开 HTTP 响应从提交事务同时取出，避免与 reset 竞态。

默认调度为 priority/FIFO first-fit；独立 external 模式为 B 保留真正可决策的 Pending 队列和版本化计划提交口。CP1 支持 allocate/defer，逐项检查已支持的前置条件；其他动作明确拒绝。没有提出调度收益结论。

## 实测范围

- Python/契约/资源/事务/HTTP/并发/审查回归：192 项通过。
- 独立 HTTP 进程验收：10 项通过，包括32路真实请求争末资源、同键重放、跨Owner隔离、租约边界、部分成功和显式结算。
- 响应丢失：发送 job 阶段请求但不读取响应；另一路确认已提交后 SIGKILL 服务，重启同一库，重放旧阶段，作业与 allocation 均未重复。
- 独立资源历史：不用生产放置函数重算 claim/release 事件及最终占用；跨线程和4个独立进程的存储测试通过。
- JSON Schema/TypeScript 一致性、Web 构建、官方原件完整性及真实主机 smoke 通过。
- 演示库存与本地身份生成脚本实际检查；没有把生成凭据加入版本控制。

`make cp1-a` 重新运行测试和 HTTP 进程验收。原始记录写入 `evidence/cp1/a_core_http_history.json`，回执为 `evidence/cp1/a_core_receipt.json`，两者在本地生成并排除 Git；CI 同样运行并上传证据 artifact。回执含构建 commit、内容指纹和运行时间，若执行中源码变化则拒绝给出整体 PASS。

## 审查中修复的问题

1. 新阶段重复绑定 allocation 曾将运行中意图降回等待；修为保留真实运行状态。
2. 普通 job POST 曾绕过 WorkIntent 绑定/结算；绑定租约现在要求使用原子 job 阶段。
3. 提交与响应读取之间 reset 曾可能产生500；HTTP使用同事务的响应快照。
4. 策略前置条件曾仅记录未核查；现逐项检查，未实现条件明确拒绝。
5. reject 动作曾记录成功但未改变需求；CP1直接拒绝未实现动作。

这些反例保存在 `tests/domain/test_cp1_audit.py`，6 项回归通过，其中包含故意在提交后、发出响应前 reset 的 HTTP 测试。

## 边界与交接

- constant-work-v1 为固定10秒逻辑模拟，不执行容器/命令，不产生真实计算结果；CPU/GPU 实测、保存/恢复、故障、回收和两预算留在 CP2。
- SQLite 当前持久化完整状态与审计历史；正确性先完成，CP4大规模/延迟指标尚未执行，不能由本轮并发测试推导。
- 本地 X-Owner 模式仅用于本机开发；三角色与验收使用服务端映射的 bearer 模式。测试密钥与用户身份严格分离。
- `make checkpoint CP=CP1` 保持 NOT_RUN（缺少联合回执）。没有以 A 的10项检查冒充双人 UI、页面刷新或六工作区通过。
- B 的 projections、queries、policies、workflows、web 目录保持未改动。最小读桥在 A 的 HTTP装配中，可由 B 接管。
- [B 接线指引](handoff/CP1_A_TO_B.md) 给出实际命令、请求格式、分页与策略模式。B 使用自己的分支，不覆盖其本地改动。
