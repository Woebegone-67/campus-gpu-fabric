# 逐页讲述、现场节奏与追问准备

2026-11-15。配合 [路演策略](STRATEGY.md) 与 [执行手册](DEMO_RUNBOOK.md)。本文件是待排练的讲述设计，不是已制作的 PPT 或已完成的录像。所有“本次”数字必须来自最终冻结构建；下列动作描述只有实际发生才能说出口。

## 1. 视觉与叙事纪律

整场只回答一个问题：**资源被收回以后，工作究竟有没有真正接续？** 观众只需要记住一个工作、一台被收回的设备、一个保存点和一个结局。

- 一页只承担一个判断。标题写结论或问题，不写“架构介绍”“技术优势”“核心亮点”这样的目录词。
- 封面允许使用织线意象；正文白/浅实底、高对比文字，用一条贯穿的工作线连接事实。每个点对应真实状态，不能随机闪烁制造忙碌。
- 状态不只靠红绿：用“已报告／已核验／已应用”“请求已受理／停止待确认／已归还”等文字与形状。动画必须能停、能跳过。
- 代码、JSON、版本号放证据附页。主页面只留一处可追溯的短标识，不让长 UUID 成为视觉中心。
- 图中理论/模拟/真实 CPU/当前实测各有文字标识；不使用真实 GPU 图片暗示完成过 CUDA 训练。
- 一次真实界面操作最多突出一个区域，避免缩小整页后让评委找字。暂停讲述也不要遮住执行模式和真实等待。
- 数字只出现三类：实际流程的起点/结果、已核验的实验结果、明确标注的示意输入。不得拿示意 KPI 装饰总览。

## 2. 五分钟核心版：七个画面，一条工作线

现场时长尚无主办方给定要求，五分钟是我们可伸缩的核心版。排练使用真实秒表；下表是讲述预算，不是给服务端设置虚假完成时限。

### 画面 1，0:00–0:25：设备是我的，工作还没完

**画面：** 左侧一句“我现在要用自己的设备”，右侧一句“我的工作还没结束”。中间只放“谁应该让步？”与项目名。

**讲述：**

> 校园里愿意共享的算力，常常也是主人随时要用回去的设备。借用者希望工作继续，贡献者希望按时收回。我们做织算，想解决的不是第一次把卡分出去，而是这两个需求发生冲突以后，系统到底能交代什么。

**评委应该得到：** 这是一个具体的双边冲突，不是又一个提交任务的网页。

**删除：** 宏大市场规模、GPU 稀缺常识、技术栈名单、没有访谈证据的用户数量。

### 画面 2，0:25–0:50：先约定什么算失败

**画面：** 真实总览的一项工作，右侧三条判据：“原执行没停就重用资源”“新执行没用保存点却叫恢复”“完成以后资源账说不清”。底部明示“真实固定 CPU 程序；GPU 库存模拟”。

**讲述：**

> 今天运行的是固定的真实 CPU 参考程序，GPU 库存是模拟的。我们先约定：如果原执行没有停就复用资源，或者新执行从头开始却说恢复成功，这次展示就失败。稍后您可以决定什么时候收回设备。

**操作：** A 已提交/打开真实工作，B 准备自己拥有的贡献设备。确认当前处于 Running 后立即进入收回操作，不为了守住页码秒数让短工作先结束。下表的分钟是旁白预算，执行步骤由真实状态驱动；不声称点击“提交”瞬间已经运行。

**不说：** “任意训练任务”“自动无损迁移”“零中断”。

### 画面 3，0:50–1:35：收回发生了，但每个绿灯含义不同

**画面：** 从总览进入清爽工作详情；评委口头选时机，B 发出本人设备的真实收回请求。时间线就地显示已观察的报告、核验、停止与等待。右侧保留设备当前是否仍占用。

**讲述：**

> 收回已经受理。这里我们刻意没有把所有步骤合成一个“成功”：程序说保存了，不等于工件已经可用；工件可用，也不等于下一次执行真的用过它。资源是否能归还，还必须看原执行是否已确认停止。

**状态驱动语言：** 尚未核验就说“等待核验”；停止未确认就说“仍不能复用”；发生失败就读出实际原因。不能为了追时间跳到下一页把未知状态藏掉。

**必须优先完成的操作：** 以真实收回回执为 T0；确认原执行已停、租约可恢复后立即提交恢复，并在实际 Pending 时马上询问“继续，还是现在取消这项工作？”不要等到画面 4 的讲述时间才问。预设通知 3 秒、占用 30 秒，窗口约在 T0+33 秒结束；这是依据请求的窗口，仍以响应中的实际截止为准。讲解可以在操作后展开，不能靠不刷新页面保住一个假的 Pending。

### 画面 4，1:35–2:35：结局由刚才的选择决定

**继续分支画面：** 展示刚才已及时选择的真实后续：同一工作，新执行代次、保存点。新执行实际起点当前不是公开页面字段，必须切到标明“本地只读执行观察”的辅助证据，按执行手册采集；B 不得从 applied 推算步数或编造实时进度。若窗口尚未结束则展示等待；若已接续则直接展示接续，不倒演状态。不强行添加隐藏容量或延长原租约。

**继续分支讲述：**

> 我们保留同一工作身份，恢复仍受原租约、资源条件与次数预算约束。真正证明接续的不是这个按钮，而是新执行确实从已经核验的进度开始。请看这个起点，它与刚才保存点的关联在原件中可以核对。

**取消分支画面：** 取消请求、终态、最终归还以及随后一次读取。已运行的取消必须等停止确认；Pending 取消不要在已启动后仍按等待分支解释。

**取消分支讲述：**

> 用户的意图已经变了。系统不能因为晚到的保存报告或恢复回调，又把它偷偷启动。我们核对的是取消的真实结果、资源归还，以及没有新执行被建立；这条观察只覆盖本次检查窗口。

**时间不够：** 当前运行继续保留；如切到备份实录，立即标明“同构建的另一次实录”，显示不同工作标识。不能把它接成当前工作已完成。

### 画面 5，2:35–3:20：结果可以带走，但结果正确还不够

**画面：** 原始 JSON 下载成功、独立核对结果，以及同一工作→旧保存点→新执行起点的最小关系图。

**讲述：**

> 最终数值可以用独立的计算方式核对。但是数值正确，仍不能单独证明我们节省了重算——从头算也可能得到同样答案。所以我们还核对新执行起点、保存点来源和停止记录。这几项加在一起，才能说明本次实际做了什么。

**取消分支替换：** 核对取消终态、无占用与观察窗口内无新执行；不展示取消工作的“成功结果”。使用已标注的完整恢复备份说明输出核对，不能抹去分支区别。

**边界：** 本地日志自洽、摘要和核对器不等于第三方公证。没有外部签名/可信锚时，不能声称恶意服务端无法重写整套证据。

### 画面 6，3:20–4:25：多检查一步，保护的是哪一方

**3:20–4:05 画面：** 对照刚才实际发生的状态，呈现策略文档 §6.2 的“容易误用的判据／额外检查／代价”三行图。只选其中一个现场对应的细节展开，不把测试数量作为价值。

**讲述：**

> 我们围绕同一项工作，把贡献者是否真正拿回资源、使用者的保存进度是否真正被新执行采用，分别核验。收到保存报告不够，发出停止命令也不够。这个设计有代价：核验会拒绝坏工件，停止确认会等待，原子提交也有竞争成本。但少掉这些条件，界面上的成功就可能比实际发生的事走得更远。

这张图是本系统设计选择的针对性验证，不是实际执行过的机制消融，也不宣称比成熟平台更先进。若 P1 合法接续/从零恢复的对照已完成且独立核对，替换其中 20 秒为该条件下的实际净收益和代价；未完成不得先放节省百分比占位。

**4:05–4:25 正文边界：**

> 我们当前的调度策略正式对照 R 精确为 1，没有证明策略收益。今天证明的是固定 CPU 程序的真实接续，尚未验证真实 GPU 训练。控制面性能按最终正式记录单独报告。

**架构口播插槽：** 仅填交付状态里的最终正式数值。如果 NOT_MET，就说“已修复确认的结构问题，但原并发延迟门槛仍未达”。不填宿主机中位数替代 p95。Owner 损害反例和行动空间诊断放备份页，提问时展开；不能把负结果隐藏成脚注。

### 画面 7，4:25–5:00：请核对这一次工作

**画面：** 同一工作的核对卡，只填实际取得的事实：停止确认、保存点与新执行起点、结果、资源结算。缺失字段明确留空并说明，不提前填入绿色完成。

**继续且完成时讲述：**

> 请看这一次：原执行已确认停止，新执行从这个保存点继续，最终结果可以独立核对，资源状态也单独列明。您可以带走原始结果，用核对器检查它，再对照新执行起点。织算要让临时借来的算力，交付一项能说明过程的工作。可收回的算力，可核验的接续。

若本次没有完成，上述已完成句子必须改成真实状态。取消分支则核对取消、占用与观察窗口内未复活；它不能证明这次成功接续。完整恢复材料只能明确标注为另一工作实例，官方视频仍必须有完整异常与恢复链。

**结束动作：** 指向一个已验证可访问、不含凭据的原件与核对方法，让评委做一次具体核对。没有公开部署就使用本地交付包，不展示未发布的二维码。以已经证明的取舍和本次事实收束，不以未来研究清单或“行业领先”收尾。

## 3. 八分钟扩展：增加因果深度，不增加模块

在画面 5 后加两分钟，画面 6 后加一分钟：

1. **一分钟拆一个错误捷径。** 用两条时序示意“发出停止就归还”与“收到停止确认再归还”；示意必须标注，不冒充发生过事故。说明正确性为何会带来等待，以及未知状态为何需要保留。
2. **一分钟拆一个验证捷径。** 展示保存文件哈希相同、最终答案相同仍不能独立证明复用；补上新执行起点与原执行的关系。让评委指出少了哪条证据会改变判断。
3. **一分钟讨论一个真实研究反例。** 两张卡与三项工作的资源窗口，解释平均目标和 Owner 服务冲突。只引用已归档的微型结果，不推成全局不可能定理。

十二分钟场合再增加第二个经过排练的合法挑战，例如无兼容资源或取消分支；不现场重跑完整负载。不用更长时间列更多功能。

三分钟短讲以 20 秒问题、80 秒同构建实录摘要、40 秒证据与机制、40 秒边界收束为准。若播放的是录像，始终明示录像，不模拟现场响应。

## 4. 官方 3–5 分钟视频单独制作

题目要求实际运行、异常和恢复。建议剪辑成约 4 分 30 秒，流程预算见执行手册。它必须包含一条完整真实恢复链；现场取消分支有价值，但不替代视频的恢复要求。

先保存完整连续录屏，之后才剪辑。等待可压缩，但画面上标出省略时长，保留原片；失败不可剪成成功，多个 work 不可拼成一个 work。字幕与旁白不得宣称原片中没有观察的状态。构建、模式、原始输入和可复查位置一起归档。

录像不出现凭据、身份文件内容、个人路径或其他用户私有工件。界面若必须重导入身份，先在录制前完成。视频中的“在线/运行中”必须来自当时服务，不能固定绿灯。

## 5. 十个最难的问题：回答框架

### 1. “恢复是基础要求，你们的创新到底是什么？”

承认基础流程本身不新。解释我们重点打磨的跨工作身份、停止、工件、新执行和结算的约束，以及如何接受一条可能推翻主张的现场挑战。随后区分“系统设计贡献”与“已证实的算法创新”：当前没有后者的正收益证明。若没有窄对照或用户验证，不宣称组合已带来量化价值。

### 2. “R=1，你们不就是没有优化吗？”

对当前正式策略实验，是的。指出固定已选工作使评分改变不了主要损失，25 组相等并非舍入。展示更换动作空间后的局部收益与 Owner 损害，解释为何拒绝上线。不能说所有算法都无法优化，也不能把低 API 延迟当作回答。

### 3. “没有 GPU，为什么叫 GPU 算力池？”

冻结公共契约与模拟库存覆盖 GPU 资源形状、归属和租约；题目允许不购买真实 GPU。固定 CPU 进程用于核验执行/保存/停止/接续。我们没有验证 CUDA、真实训练工期或模型显存行为；真实适配需要应用 checkpoint 协议、设备调度与隔离、性能校准和新的验收。

### 4. “怎么知道不是从头重算？”

最终答案相同不够。检查当前候选的保存工件、来源绑定、新 attempt 实际加载起点与后续结果；独立核对器不调用生产推进函数。必要时打开原件逐项解释，不拿截图的绿色徽章代答。

### 5. “停止命令发出后设备就能给别人吗？”

不能。执行停止必须被确认，未知时不能安全复用。说明隔离行为及对可用容量的影响；不承诺操作系统永远能在固定时间杀掉任意进程。贡献者回收意图和系统已安全归还分别显示。

### 6. “没有替代设备，或者保存失败呢？”

按当前工作策略、原租约、次数预算进入等待/合法重试/失败。读出实际状态和下一步，不无限重试、不偷偷加资源、不刷新到期时间。若现场没测该分支，展示同构建实测记录或明确未测。

### 7. “设备是我的，为什么不能看跑在上面的任务结果？”

设备归属授权收回，不授予对另一位 Owner 工件的读取权。普通个人可以同时借用和贡献，但每个对象仍有归属边界；管理员权限也不能当成任意工件代理。用已经验收的跨 Owner 请求说明，不展示私人 token。

### 8. “你们的哈希日志能防止自己伪造吗？”

它支持检出不一致和独立重放，不自动提供对恶意服务端的外部信任。验证依赖保存的原件与可信锚；若整套数据和锚都能被同一人改写，单靠哈希不能证明历史真实性。当前不宣传不可篡改公证。

### 9. “规模性能不达标，怎么谈最终产品？”

准确说这是具有边界的候选原型，不能称最终通过。解释全历史写成本的修复与剩余瓶颈，给出原规模、全样本和真实未达结果。之后说明下一次验证要改变哪个结构条件；不为了演示缩小规模后仍写 PASS。

### 10. “换一个人能跑吗？哪些代码是 AI 做的？”

提供实际已完成的干净部署与测试记录；缺 B 本轮记录就明说。说明 AI 参与代码、分析和文档，团队负责理解接口、修改设计、核对回放和解释失败。来源声明与依赖许可随包交付，不用“纯手写”制造无关优势。

## 6. 排练评审，不靠自己感觉精彩

第一轮由不了解实现的人观看，只问五个问题：项目解决谁的冲突、这次是否真正接续、凭什么知道、现在不能做什么、哪处需要自己处理。答不出来就改画面与措辞，不先加介绍页。

第二轮让对方打断：“这不是重算吗”“资源真的归还了吗”“没有资源怎么办”。观察 A/B 是否能在 30 秒内定位一条实际记录，而非背技术名词。30 秒是排练目标，不是系统性能声明。

记录实际总时长、超时点、术语解释次数、观众误判、依赖人工协助和失败分支。两轮是交付前的计划，不是本文件已完成的测试。

## 7. B 的最终画面交付

必需画面只有五组：个人总览；工作详情的中断过程；本人设备收回状态；原始结果查看/下载；供追问的证据抽屉。新设计不得把已有权限、稳定 ID 重试、原始 JSON 大整数、故障状态或合法动作判断覆盖掉。

交付时提供实际运行截图与连续录屏、前后端提交号、测试设备与浏览器、当前未实现项。设计稿可以标注示例，但不能进入正式视频冒充实时产品。手势让叙事更顺畅，真正的亮点仍是观众能看懂并核验刚才发生的事。
