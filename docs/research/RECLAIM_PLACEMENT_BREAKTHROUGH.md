# 收回权创新复核：可完成性匹配与神经可用性预测

基线提交：`0217e45de5bac7c8217c0144d51ff6414331d2f5`。研究分支：`research/b-reclaim-breakthrough`。日期：2026-11-15。

## 结论与决策

**交付收敛（2026-11-15）**：按用户最新要求，停止额外调参和复杂优化，交付核心神经分配算法及实际 worker 接线。896 条合成训练样本不足以证明真实场景性能；数据量小及代表性不足列为重要限制和可能原因，不将尚未做过的规模消融写成“负面结果主要由数据量导致”。下面保存已完成的研究原貌，后续产品交付不以追逐更高百分比为前提。

旧评价确实没有覆盖截图中的“可用窗口 × 任务中断代价”匹配；但已经实现的通知后单任务规划本身也接近当前候选集合的收益上限。继续微调保存时机或等待权重，不足以支撑更强的核心创新。

本轮先实现事前联合匹配，再用上限审计判断它是否足够。第一轮只有一次收回的模型仍然缺少总体性能空间，因此第二轮进一步检验：**任务是否能在反复出现的可用窗口中逐步完成，还是反复从头重算；有限的稳定设备应留给哪项工作。** 贡献者按时收回是各策略共有的硬约束，不拿“禁止主人收回”的系统作弱基线。保留旧机制及每轮原始证据；新策略保持实验性、可选，不直接替换产品默认策略。

## 为什么旧默认只有 0.48%，另一模式反而变差

使用原协议重新执行，140 行主结果与封存 `report.json` 逐项一致。只读复核程序为 `experiments/research/reclaim_diagnosis.py`，输出在 `evidence/reliability-placement-20261115/notification-headroom.json`。

| 原模式 | 能完成则完成、否则立即保存的成本 | 自适应成本 | 相对改善 |
|---|---:|---:|---:|
| 尽快归还 | 67.114286 | 66.792857 | +0.478927% |
| 尽量保留计算 | 66.241071 | 67.111607 | −1.314193% |

这里的成本是“归还后剩余计算 + 保存/重启开销 + 等待权重 × 贡献者等待”，不是吞吐或实际 GPU 加速。默认模式的平均完成时间反而从 79.078571 秒到 79.114286 秒；它用一个案例里额外 0.5 秒的重算换取更早归还，不能称为所有指标同时改善。

设延后保存 d 秒，且最终保存成功、任务未提前完成，那么：

`J(延后) − J(立即) = −d + λd = (λ−1)d`

默认 λ=1，继续计算的收益与主人等待严格抵消。强基线已覆盖“能完成则完成、否则保存”，自适应只在零进度/很低进度且保存昂贵的两例略优，其余十二例相同。

进一步逐案例事后从现有五种策略挑最低成本，默认模式的改善也只有 **0.489570%**，当前策略距离它仅 **0.010694%**。这是“当前候选集合的事后诊断”，不是所有可能算法的理论上界；但它足以否定在相同动作和输入上继续寻找数量级提升的合理性。

λ=.25 的保留模式则天然趋向最晚保存。在保存耗时低估案例中，它损失 34.7 等价计算秒，成本多出 30.175，抵消了其余七例收益。停止耗时低估还导致一例超期。当前 CPU 保存耗时上界取自进度采样间隔代理，并不是经过覆盖率校准的保存延迟分位数；通知后也没有持续重新规划。解决这些问题有可靠性价值，但现有候选集合在保留模式的事后最好改善也仅 2.458552%，不能把修复错误当成足够大的机制创新。

## 哪一部分此前没有做

旧 `policies/reclaim.py` 只在任务已经位于某张卡、已经收到通知后决定动作。原 `policies/candidate.py` 中恢复成本组件因为缺少已验证的 profile 而未激活。于是：

- 旧实验不评价把哪种任务分到哪张卡；通知前的错误匹配已经被固定。
- 相同型号但不同连续可用时间的设备，在该环节没有体现差异。
- 单任务自己选“最稳定的卡”，可能提前占掉另一个高损失任务更需要的稳定资源。

两个设备风险为 pH、pL，两任务中断损失为 LH、LL 时，相对反向匹配，合理匹配的期望减损为 `(pH−pL)(LH−LL)`。这只是解释交互的简化模型，不是本轮测得的收益。没有风险差异、没有任务代价差异、根本不发生中断，都应没有系统性收益。

## 实现及不可越过的边界

新文件 `src/campus_fabric/policies/reliability.py` 提供显式实例化的 `ReliabilityPolicy`：

1. 复用 B2 的合法候选和首个获准需求，不借可靠性评分插队；针对当前可同时安排的有限需求集合做匹配。
2. 只接收过去已完成可用窗、预先声明的通知期、任务计算和保存 profile。禁止读取未来 recall、实际结局；租约 TTL 和任务 timeout 都不充当工期。
3. 边成本是历史窗口下的单次中断预计重算与保存/重启开销。可完成则完成；能保存则计保存成本；保存来不及则计已执行而丢失的进度。
4. 使用有界精确匹配，一次仍只提交一个合法候选。没有私建预留账本；提交后重新读取快照并计算后续分配。
5. 同分尽量保留 B2 首个选择。数据不足、过期、矛盾、候选截断或无法完整匹配时回退 B2。

当前支持最多六项需求、六个独立单整卡节点。多卡节点、MIG、CPU-only、超范围快照回退。现有默认库存包含多卡节点和 CPU 节点，因此**不会自动启用新匹配**。这是刻意的支持边界，不声称覆盖一般集群装箱问题。

过去完整窗口不是天然可信的未来概率：还存在正在进行的窗口被删失、短窗口更易被采到、当前窗口已持续多久、用户行为突变等问题。仅靠四个样本和有效期门槛不能保证预测质量。生产启用需要可靠的数据来源与预测校准；本轮不发明这些数据。

## 对照方案

见 `experiments/research/RELIABILITY_PROTOCOL.md`。在查看结果前固定九组条件 × 二十个配对种子 × 六策略；历史样本与未来结果独立生成。所有策略面对相同需求、相同设备、相同收回处理规则。

基线包括 ID 放置、稳定优先 FCFS、长任务配稳定卡、最高预计中断损失配稳定卡、同成本逐项贪心；新机制是有界联合匹配。明确包含无中断、同质设备、同质任务、无信息历史、历史反转、运行时间估计错误等反例。

主指标为重算加保存/重启开销，另列完成时间、批次完成时间、每个任务受损情况、主人等待、归还超期。不用新的加权分数掩盖硬约束，也不把新指标百分比和旧 0.48% 直接相减。

封存第一轮 `evidence/reliability-placement-20261115-run01/` 含 1,080 条主实验结果与另列的 1,080 条禁止冷重启控制结果。

| 九组等权平均 | 同成本贪心 | 单次损失联合匹配 | 变化 |
|---|---:|---:|---:|
| 每批重算与保存/重启开销 | 5.7140 秒 | 4.2745 秒 | 下降 25.19% |
| 平均完成时间 | 68.0988 秒 | 66.9590 秒 | 缩短 1.67% |
| 批次最后完成时间 | 119.0145 秒 | 119.9609 秒 | 恶化 0.80% |
| 归还超期 | 0 | 0 | 相同 |
| 严格控制完成数（另列） | 704/720 | 715/720 | 增加 11 项 |

**25.19% 不是整体算力提升。** 全部节省 259.111 秒，仅占 43,216.142 秒实际有用工作量的 **0.5996%**。104 项任务更快、65 项更慢，最大变慢 24.081 秒。历史风险反转时开销反而增加 **29.04%**；同质和无中断条件没有实质收益。短通知严格控制中，简单 loss_sort 完成 76/80，联合匹配只有 75/80，不能挑选弱基线宣称全面领先。

随后枚举每案例全部 24 个分配，对每个目标分别计算事后最优，累计检查 8,640 个分配结果；原有 2,160 行逐项重放一致。事后最优可以把相对贪心的开销节省扩大到有用工作量的 **1.3210%**，但平均完成时间最多改善 **3.6224%**。三个目标的最优分配不同，不把它们拼成一个不存在的万能策略。证据为 `evidence/reliability-placement-20261115/headroom.json`。

这轮结果说明联合匹配能减少局部损失，但不足以作为总体突破。其根本限制是：模型在一次收回之后假设资源永远稳定，长任务不会再次遭遇中断。

## 第二轮：反复收回与重启陷阱

如果保存时间超过通知窗口，一个长任务可能每次只运行一小段就丢失进度。把它继续放回类似设备，不是多花一次保存费用，而是可能一直完不成。相反，容易保存的任务能够通过多个短窗口累积进度。只按平均可用窗口、任务长短或下一次损失排序，都没有直接表达这个差别。

新文件 `src/campus_fabric/policies/renewal.py` 用历史窗口的经验分布估计反复中断下的完成时间。状态包含剩余工作量、剩余恢复次数、距观察截止的时间，以及首次启动/恢复启动；恢复开销消耗下一段可用窗口。保存成功才能积累进度，无法保存时重新执行最近保存点之后的工作。所有数据边界、合法候选、B2 获准顺序与回退条件继续复用第一轮。

预测模型采用一秒保守离散，在每条路径上分别截尾，计算离散经验模型下的 `E[min(T, 900)]` 以及截止前完成概率；它们都尚未经过真实轨迹校准。无观测完成窗口只表示该经验模型给出高成本，不能据此断言真实任务永远无法完成。先前的无限恢复分析函数仍保留为独立诊断，主策略不使用它。

第二轮协议见 `experiments/research/RENEWAL_PROTOCOL.md`：沿用相同 180 组任务和历史数据，在看结果前固定反复出现的独立设备窗口、900 秒观察期、八种策略。每项任务固定设备，所有策略使用相同连续时间执行器和通知响应，恢复会真实消耗后续窗口。系统契约默认的两次恢复上限也对所有策略生效，不给新策略额外尝试机会；租约和 timeout 明确配置为合法的 900 秒，不能称为默认 300 秒租约的结果。

主指标为所有已接纳任务的限制平均完成时间，同时报告真正完成数。预算耗尽保留为已知阻塞未完成，观察期结束仍运行的另列删失；两者在完成时间指标里都计 900，不能把 900 当作真的完成时间。新增同成本 renewal 贪心强对照，保留所有历史反转和无信息控制。

第二轮已冻结并执行，完整证据在 `evidence/reliability-renewal-20261115-run01/`。九组等权、180 个配对案例、每策略 720 项任务，所有案例均保留：

| 分配机制 | 限制平均完成时间（秒） | 900 秒内真正完成 | 恢复预算耗尽 |
|---|---:|---:|---:|
| 按设备 ID 分配 | 252.4161 | 556/720 | 164 |
| 按稳定程度给先到任务分配 | 230.4678 | 576/720 | 144 |
| 长任务匹配长窗口 | 177.9838 | 625/720 | 95 |
| 下一次损失排序 | 208.6424 | 594/720 | 126 |
| 原一次中断成本联合匹配 | 219.2626 | 582/720 | 138 |
| 新有限恢复成本，逐项贪心 | 219.5683 | 585/720 | 135 |
| **新有限恢复成本，联合匹配** | **160.3289** | **637/720** | **83** |

相对表现最好的简单对照“长任务匹配长窗口”，限制平均完成时间减少 **9.92%**，完成率从 **86.81% 到 88.47%（+1.67 个百分点）**。相对相同成本的逐项贪心减少 **26.98%**，多完成 52 项；配对 seed bootstrap 的绝对减少区间为 [44.94, 74.62] 秒，仅刻画此合成生成器的变动，不代表真实总体。

所有策略归还超期为零，新增机制没有延长主人设定的硬期限。但主人等待没有全面降低：每批累计平均 11.2853 秒，相同成本贪心为 11.0865 秒。相对该贪心，137 项受益、113 项更慢，最坏一项由 60 秒完成变成预算耗尽后计 900 秒。稳定性反转与无信息组的区间覆盖零，同质设备组略差。联合平均最优不等于每位用户都获益。

这一证据支持的突破是**用可完成性和有限恢复预算决定资源匹配**，不能描述为 GPU 实测加速 26.98%，也不能隐藏完成率的绝对增量。900 秒口径、两次恢复预算以及同一任务固定设备的假设均限定了适用范围。

## 第三轮：神经预测已经改变分配，但收益不能归功于神经网络

按用户确定的 pipeline，新实现不是在每张卡旁边附加一个风险分：它从过去已经可见的供给窗口与公开日历提取特征，实际训练一个 8→16→8 MLP，预测可用窗口分布，再结合每项任务的工期、保存成本与剩余恢复预算形成任务×设备成本矩阵。`task_gpu_rankings` 输出随任务变化的排序，联合分配生成已有合法候选；收到实际收回通知后仍执行原保存/停止/恢复机制。

模型使用真正的反向传播，包含右删失似然；896 条训练样本、224 条诊断验证样本按时间严格分隔。模型和超参数只训练一次，验证集不选模型。四个测试组各 16 个固定时点，共 64 个配对案例、五策略 320 条结果。本轮没有可用的真实贡献者轨迹，因此全部标为**合成研究**。协议、输入、源文件和权重分别固定哈希，见 `evidence/neural-availability-20261115-run01/`。

| 相同有限恢复成本与准入集合 | 限制平均完成时间（秒） | 完成数 / 256 |
|---|---:|---:|
| 全体历史分布 + 联合匹配 | 271.0469 | 211 |
| 每位贡献者历史分布 + 联合匹配 | 272.3770 | 210 |
| **同一时段历史分布 + 联合匹配** | **265.2148** | **211** |
| 神经预测 + 贪心 | 267.0410 | 212 |
| 神经预测 + 联合匹配 | 267.4473 | 211 |

神经联合匹配相对同一时段统计**恶化 0.84%**，完成数相同；相对同一神经成本的贪心也没有改善，少完成一项。相对时间分桶，33 项工作变慢，最坏变慢 741.5 秒（未完成按 900 秒计入），必须保留。所有策略归还超期均为零。四个测试日的差值方向不一致，不能据此声称神经机制必然更差，也不能声称已经建立优势。

预测质量和分配质量并不是同一件事。在规律稳定组，神经 NLL 为 1.2446，优于时间分桶的 1.3208（越低越好），但完成指标为 253.0781 对 235.7422 秒，反而更差。在未见贡献者组，神经完成指标为 227.8281 对 229.9766 秒，只有小幅改善；行为突然反转时，神经 NLL 升到 3.0672，无信息组为 3.1410，显示不能把既有周期模式当成保证。

为区分随机结局与成本相关预测错误，额外进行了**事后诊断**，不重训、不选新种子、不改策略：重放原 320 条结果全部一致，枚举 1,536 个未来已知分配；另用合成生成器的真实概率分布计算同一近似成本模型下的期望分配遗憾。稳定组神经平均遗憾为 12.731 秒，时间分桶为 5.204 秒；这说明该组的问题并非全部可归咎于少量测试时点的偶然性。无信息组所有设备真实分布相同，期望遗憾均为零；实际胜负变化来自随机未来，不能拿这种事后赢家当预测可学到的提升。

原因是平均概率似然奖励“总体分布像不像”，而长任务的价值取决于特定完成阈值、保存能否在通知内完成、两次恢复之后还能否成功。少量与这些阈值相关的概率或相对排序误差，会被联合匹配放大。当前特征还把设备习惯压缩成近期统计；数据不多、已有简单时段规律很强，加入 MLP 本身没有额外优势保证。该研究也未比较使用相同特征的线性学习模型，不能证明神经架构是必要条件。

**本轮决策：保留已经实现的神经训练、排序与合法分配通路，维持显式实验选项，不把这次合成权重设为产品默认，也不为得到漂亮数字继续扫参数。** 有证据的机制突破仍是上一轮的有限恢复可完成性匹配；神经网络的额外收益尚未证明。下一项值得研究的假设是围绕任务完成阈值评估预测校准与排序损害，并在真实连续供给记录上检验行为变化后的退回机制；这需要新的预注册轨迹实验，而不是继续换一种分母报告收益。

## 内核兼容验证

`tests/policy/test_reliability_kernel.py` 使用真实隔离 SQLite 内核：

- 同一获准顺序下，短且易处理任务使用短窗口设备，长且高保存代价任务使用稳定设备；逐次提交，不重复占卡，工作完成后租约正常释放。
- 过时版本的计划被拒绝；声明通知期 12 秒也不能阻止贡献者实际发出 1 秒通知，实际期限后租约进入 Preempted。
- 没有研究适配器注入的资料，选项与 B2 相同。

这证明契约与权威账本兼容，**不证明真实 GPU 的性能收益**。测试里的任务完成使用原逻辑模拟时钟。

另外使用上面的真实训练权重，在预先固定的 `predictable/index0` 案例上进行了独立 SQLite 回放。只读取该案例的已观察历史与声明 profile，不读取隐藏未来或结果报告。四次神经计划均由 A 提交；前两次实际改变了 B2 的选卡，四张卡没有重复占用。贡献者随后将实际通知期缩短为 1 秒，内核仍按该期限收回；原 900 秒租约到期不被模型延长，旧版本计划仍遭拒绝。见 `evidence/neural-kernel-replay-20261115-run02/RECEIPT.md`。`run01` 因新增回放脚本把严格 tuple 字段传为 list 而失败，修正仅限该脚本，使用同一个预定案例重跑；失败产物保留，未重训或更改正式对照研究。

## A 线接入前需要提供什么

若后续决定进入产品联调，应沿现有快照契约补充资料生产链，而不是让前端捏造评分：

| 字段 | 来源/约束 |
|---|---|
| `DemandSnapshot.known_data: estimated_compute_seconds, checkpoint_seconds` | 明确声明或可审计历史 profile；source_id 对应 demand_id；保留误差和可用时间；不读 TTL |
| `DecisionSnapshot.history: availability_window_seconds` | physical_gpu_id 关联、截至当前已观测的完整窗口；实际采集需要处理删失/曝光时间，不能仅按收回次数排序 |
| `DecisionSnapshot.metadata: notice_seconds` | 贡献者声明的通知服务条件，不是下一次收回事件的隐藏时间 |
| `DecisionSnapshot.metadata: owner_use_seconds` | 已声明或可审计的贡献者占用时长 profile，不能偷读未来实际占用 |
| `DemandSnapshot.known_data: remaining_recoveries` | A 的当前真实 `max_restarts - restart_count`；来源 public_metadata/observed_event，研究 wrapper 仅支持 0–2，超出回退 |
| `DemandSnapshot.known_data: execution_window_seconds` | A 核对的剩余租约与任务 timeout 的较小值，未获租约时使用相应声明值；本研究 wrapper 要求至少 900，否则回退 |
| 时间与权威 | observed_at ≤ available_at ≤ now；A 内核继续校验资源、版本、权限与真实收回截止 |

不能因为研究模型的结果好，就让最新的人工填写 profile 直接作为“可靠性保证”。先做影子决策与误差测量，再决定是否扩大支持形状和开启真实放置。

## 相关工作与创新表述

可靠性分层、抢占式资源和 checkpoint 调度已有丰富研究。[Proteus（EuroSys 2017）](https://www.pdl.cmu.edu/ftp/BigLearning/proteus_abs.shtml)研究不同可靠性资源中的机器学习弹性；[Can't Be Late（NSDI 2024）](https://www.usenix.org/conference/nsdi24/presentation/wu-zhanghao)讨论不可靠 spot 资源与完成时限，并用真实云轨迹评估。不能宣称本项目首次提出“风险感知调度”，也不能借用论文里的收益数字。

适合本项目的贡献表述是：**在贡献者可按时收回的共同约束下，结合任务中断损失、设备可用窗口与有限恢复预算进行可解释分配，并用通知、保存、核验、恢复与资源归还的真实状态链核对结果。** 本轮实现了有界匹配和可选的神经预测通路；可完成性匹配具有上述合成证据，神经预测的额外收益、生产可靠性和真实 GPU 训练效果尚未证明。
