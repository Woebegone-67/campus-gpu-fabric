# CP3：为何 R=1.00，以及何时停止这条路线

2026-11-14。结论：当前 P 在注册的125次正式实验中没有净收益，应冻结继续微调。瓶颈主要是动作空间与目标错位。新方向存在局部可证的空间，但不能用平均指标的改善掩盖 Owner 损害。按用户授权进入 CP4 开发与独立挑战，保留所有未达结果及质量义务。

## 1. R=1.00 的直接原因

只读复核原 `1cc2ab6` 封存材料，所有读取文件均对照登记 SHA。P/B2、runner、输入生成器和库存从该版本到修复版 `e2a768f` 没有变化。没有重跑125次，也没有用旧验证种子调参。

P 先执行 B2，再限制在 B2 已选工作的候选放置中选择。它不能改变先服务哪个工作，不能选择成批准入、等待或预约；恢复时机仍由 runner/workflow 控制。恢复成本项没有真实可用模型，明确未启用。见 `src/campus_fabric/policies/candidate.py`、`baselines.py` 和 `experiments/cp3_runner.py`。

| P 的25次正式运行 | 实测数量 |
|---|---:|
| 决策快照 / 选中动作 | 1,564 / 790 |
| 已选工作有多个合法放置 | 323 |
| 这些放置具有不同节点或资源形状后果 | 34 |
| 已选工作候选间机会分数有差异 | 26 |
| 最终改变同状态 B2 的选择 | 3 |
| 候选预算截断 | 0 |

764/790次选中动作的机会分数完全平局；其余26次中23次仍与 B2 选同一最小值。评分使用字典序，没有一个等待精调的权重；已观察最大候选数192，增大512预算也缺乏依据。计算了非零分数，不等于改变了可影响结果的动作。

23/25对完整动作序列一样，24/25对逐工作结果完全一样，即798/800个工作相同。仅 waves401 的 work02晚10秒、work04早10秒，面积恰好抵消。三次动作变更都在 waves，其中两次只交换 A10/A100 放置，同一时刻仍启动、完成同一组工作。**25组面积各自精确相等，R=1.00 不是显示舍入。**

当前模型对所有工作使用同一10秒工期，放到 A100 不会因此更快；runner 在同一时刻连续分配，再统一启动新任务。很多设备交换处于等价状态。机会损失代理与最终完成时间之间没有建立足够强的联系。

## 2. 先分解损失，不改分母

原 B2 每族5个种子的 F 分解如下，单位为逻辑秒。F 对失败、取消和未完成任务计至 H，全部工作保留。

| 场景族 | 总 F | 完成任务10秒基数 | 完成任务排队/中断等额外历时 | 失败 H−r | 未完成 H−r |
|---|---:|---:|---:|---:|---:|
| compatibility | 14,650 | 1,400 | 5,500 | 0 | 7,750 |
| waves | 7,700 | 1,520 | 3,260 | 0 | 2,920 |
| recall | 24,192 | 1,430 | 15,962 | 6,800 | 0 |
| node | 30,786 | 1,150 | 11,936 | 17,700 | 0 |
| neutral | 8,600 | 1,600 | 7,000 | 0 | 0 |

这些结果提示，关键问题包括准入排队、连续性和供给中断，不能只看同一个工作占哪张卡。失败/未完成份额不是不可改进下界，也不能为了做出收益删掉。该分解不证明全体调度算法已无改进空间。

## 3. 从旧 MCM 迁移的经验

旧工程最终决定记录了三条重要经验：

- Q2 准入与预约机制相对同框架强 SJF 减少总等待31.0647%；它改变了资源承诺和工作顺序。
- 后期本地版本只再省64,848作业秒，却让34,520项工作更晚，最大新增等待3,770,618秒，最终没有替换正式方案。
- Q3 同一共享资格域内 placement 收益约2.2627%；扩大型号兼容资格带来的系统变化必须另算，不能归功于 placement。

六轮总结也保留了“更精确的已知队列 critic 反而增加总成本”的反例。可迁移的是诊断方法：先问动作能否改变损失，再对照完整流程和个体损害。不可直接迁移的是已知工期、等速跨型号、零迁移开销或离线未来信息。

本轮读取的来源是旧工程 `FINAL_MCM_B_20261018/01_PAPER_HANDOFF/00_FINAL_DECISIONS.md`、`04_REPRODUCIBLE_CORE/outputs/ablation_A10/results.json` 及 `ARCHIVE/legacy_workspace_20261018/research_delivery/六轮研究总结与理论深化报告.md`。这些为既有结果，本轮没有重跑旧 MCM 或重新认证其全局下界。

## 4. 新方向的实际鉴别，而非换一套分数

新增研究脚本只在隔离临时数据库运行，不修改产品策略。候选放宽“固定 B2 工作”的限制，在当前合法候选中偏好能与更多当前工作共存的动作，并有20秒等待保护；这只是两两共存代理，既不是精确批优化，也没有证明公平性。策略只读取当前快照，不知道未来到达或真实工期。

先声明5个微型输入，共11次比较；再针对尚未验证的 Owner 风险声明1个收回反例，共2次比较。所有工作和负结果都计入 F：

| 鉴别场景 | B2 的 F | 新原型 F | 实际解释 |
|---|---:|---:|---|
| 两张卡：一项双卡、两项单卡，同到达同工期10秒 | 50 | 40 | 先运行两项单卡可省20%；现有 P 仍为50 |
| 合法 TTL30、统一工期20秒 | 100 | 80 | 原租约失败假设被推翻，全部完成 |
| 四项同质单卡任务 | 60 | 60 | 中性结果 |
| 原三项工作后，T15到达双卡工作 | 65 | 55 | 仅该微型输入成立 |
| 同一前缀，T15改为单卡工作 | 65 | 55 | T15之前的决策前缀一致 |
| 原三项工作，T10贡献者收回两卡至观察窗外 | 170 | 100 | 完成数1→2，但宽工作 Owner 的服务1→0，违反80%保护 |

这证明工作选择有当前 placement 路线之外的局部空间，**不证明新算法获得正式 R≤0.85 或总体20%收益**。38个旧真实快照也有“一项双卡工作和两项可共存单卡工作”的动作空间见证；这仍不是总体收益估计。

最后一个反例解释了为什么不能只追求平均值：三项工作全部完成需要40 GPU秒，收回前两卡只能提供20 GPU秒；保留 B2 宽工作 Owner 的至少80%完成服务意味着必须完成其唯一工作，于是没有容量再完成两项单卡工作。在这个明确的小实例中，同时获得那部分面积收益并保留该 Owner 的服务不可能。它是局部资源约束证据，不是一般在线不可能定理。

租约反例的失败假设也应保留：首次获配时 `expires_at=now+ttl`；推迟首次获配不会消耗 Pending 阶段的 TTL。该例宽工作在T20获配、T40完成、T50到期。恢复保留原到期时间，不能把这个事实误读为每次恢复都重置 TTL。

输入和复验纪律：初次TTL15被真实合约拒绝（最低30），原失败 manifest 和部分输出保留；随后更正为合法TTL30/统一工期20。独立检查还发现继承的 MODEL 描述保留H400/32项等旧文字，实际运行参数为顶层H80、3–4项。原封存材料不回写；修正元数据后对同13个微型运行作一次机械复验，逐工作结果保持一致。没有调整策略参数，重复不增加独立样本数，未重跑125次。

## 5. 冻结决定与有价值的重启条件

**冻结当前固定准入、机会放置评分路线，以及无服务保障的成批准入原型的产品推广。** 保留 B2、P、负结果和原证据，不增加候选预算，不继续做权重、微小 tie-break 或代理精度搜索。本轮原型没有替换线上策略。

仅保留两条值得未来重新立项的方向：

1. **有服务保障的成批准入与预约。** 明确 Owner 已承诺服务、等待债务、允许的收益/伤害边界，在资源当前可行域内选择工作组合。先满足服务底线，再优化 F。要求在新的有利、中性、逆向、持续小任务涌入及收回输入上均守住 Owner/个体条件；遇到上述不可同时满足的情形必须报告边界或回退，不能改评分分母。
2. **以可核验剩余工作为中心的连续性决策。** 先提供已验证保存进度、恢复开销、已公开资源窗口，再判断恢复、冷启动与等待。零保存进度控制组应无接续优势，恢复开销过高应出现反向结果，真实 CPU 结果必须与不中断对照一致。没有这些信息和模型前，不调“恢复成本权重”，更不能把 timeout 当工期。

新机制至少需改变真实动作、在完整工作队列上有收益且守住伤害限制，才值得重新冻结新的验证输入。旧125次只作历史诊断，不再用它挑选赢家。兼容资格扩展可另立研究，但必须核验能力、显存和迁移代价，独立报告可行域变化的贡献。
