# 织算：双人24小时正向开发作战书

2026-11-14 · 以正式成品为起点

本计划取代上一版“先底座、再创新、最后界面”的串行安排。目标以[终态产品定义](01_终态产品与独立复审.md)为准：三角色、六工作区、全部冻结API、持久控制面、真实CPU参考恢复、可解释决策、基线/消融和正式交付。下文为待实施计划，不是已完成记录。

T0指正式开始实施的时刻，Hn指T0后n小时；提交绝对时刻以赛事实际要求为准。预算不是能力上限，也不是到点自动降低标准的理由。

## 1. 两个人各自拥有一条完整产品主线

### A：可信资源与执行主线

**最终交付一句话：每个资源承诺、回收和恢复都真的发生，并能在故障后对上账。**

A拥有：

- 资源与MIG-like映射、allocation/job/attempt/checkpoint领域模型。
- 唯一写命令入口、原子账本、权限、幂等与持久事件。
- 逻辑时钟、同刻事件、租约、回收、预算、故障和旧代次隔离。
- 全部写HTTP适配、测试控制、贡献者及工作意图扩展的写命令。
- 模拟执行适配、真实CPU参考执行、控制面崩溃恢复。
- 构建、部署入口、领域与并发验证、机制和真实迁移说明。

### B：服务决策与操作体验主线

**最终交付一句话：用户可以完成整项工作，理解每个决定，并看到策略是否真的改善服务。**

B拥有：

- 六个工作区、统一设计系统、三角色旅程、终态结算卡。
- 查询投影、读API、事件时间线、实际decision解释。
- 调度策略接口实现、B0/B1/B2基线、候选与消融。
- 工作意图流程编排、任务配方与声明性能模型、实验运行器。
- 同条件效果分析、个体损害、实验产品和证据浏览。
- 前端/策略/查询验证、产品和实验说明、演示制作。

B不承担所有测试、所有文档和A的写API杂务。A也不独自承担算法、后台、部署和整套审稿。每人都对自己的模块自测、写说明，再在固定checkpoint互换操作者挑战对方的成果。

## 2. 交汇机制：固定接口，减少等待

两人的共同边界只有几组稳定对象：`CommandEnvelope`、`CommitReceipt`、`DecisionSnapshot`、`DecisionPlan`、`CommittedEvent`、`ReadSnapshot`、`WorkIntent`、`EvidenceRun`。定义见[交汇契约](03_交汇契约与验收规格.md)。

- A向B提供不可变的状态与决策快照、原子命令结果和已提交事件。
- B向A提供纯策略计划、原因与候选记录；计划本身不能扣资源。
- A复查计划版本和物理/合同约束，决定能否提交。
- B的页面、实验和读API消费同一状态，不维护第二份业务真相。

公共API不动；扩展和内部契约独立版本化。官方未细化的语义放在集中配置与解释表中，收到答疑时局部调整。不能因一处fault字段编码或预算边界变更，重写应用主干。

### A、B具体在哪些文件交汇

以下为拟定目录，尚未创建产品实现：

| 目录/对象 | 唯一写负责人 | 对方如何工作 |
|---|---|---|
| `contracts/`、`semantics/`、后端依赖锁 | A合入，两人CP0共同确认内容 | B提交带原因和兼容方案的精确diff |
| `domain/`、`storage/`、`clock/`、`auth/`、`executors/` | A | B只调用公开的内部接口 |
| `api/mutations/`、`api/test_control/`、`api/extensions/mutations/` | A | B提供用户动作的输入/回执需求 |
| `projections/`、`api/queries/`、`api/extensions/queries/` | B | A提供已授权、一致版本的快照 |
| `policies/`、`web/`、`workflows/`、`experiments/` | B | A用合同检查器与黑盒攻击计划和操作 |
| `tests/domain/`、`tests/concurrency/`、`deploy/` | A | B于节点执行独立HTTP核验 |
| `tests/policy/`、`tests/ui/`、`tests/blackbox/` | B | A于节点检查信息权限与产品操作 |
| 前端依赖锁与前端构建 | B | A消费构建产物，不同时改锁文件 |
| 后端启动/路由装配与最终发布 | A | B交付`register_queries`、策略注册和Web构建契约 |
| 模型、实验、产品与视频说明 | B | A提供执行/真实环境部分，审指标口径 |
| README、机制、部署、迁移和限制 | A | B提供用户流程/实验章节，各自直接维护自己的章节 |

固定各自开发分支或不重叠文件树，使用独立端口、状态库和run目录。集成环境不承担个人调试。任何实验reset只影响自己的实例，不能清空另一人的调试或录制现场。

### 不等待对方写完再工作

CP0确定契约样例和错误样例，供组件开发与类型检查；样例不是产品成绩。A在H1—H5尽早提供使用正式CommandCommit的开发host，B持续接入已实现的真实操作。尚未完成的分支可继续用契约样例开发布局/纯函数，但H5正常旅程、H10动态旅程必须接到真实服务。

流程编排属于B的服务端持久工作流，所有持久写入归A。特别是冻结POST /v1/jobs没有声明幂等键，仅在创建之后记录关联还不够。A提供内部`create_job_and_bind(intent_id, stage_id, expected_revision)`：创建job、绑定意图、保存阶段回执同事务；同一阶段重试返回原结果。allocation阶段同样保留稳定身份和回执。B不得在前端维护“我觉得已经创建过”的唯一依据，也不给纯规范客户端强加新字段。这样才能覆盖创建成功、响应丢失或编排器重启的窗口。

## 3. 六个高标准checkpoint

**每个节点约20分钟，包含在总预算内。** 除数据正确性或安全阻断外，中间不临时开会、不要求对方随时切任务。双方在节点前预跑自己的检查，携带可操作构建、具体证据和不超过三项跨边界问题。

| 节点 | A的连续主线与交付 | B的连续主线与交付 | 共同验收必须看到什么 |
|---|---|---|---|
| **CP0 · H1：终态与交汇冻结** | 领域对象、状态/占用表、事务/持久化边界、时间规则、执行适配协议、写路由清单 | 六区布局、三角色完整故事、查询/decision合同、基线和实验主指标、结果结算交互 | 21个操作均能映射到对象、事件、页面和验证；普通贡献者扩展合法；没有两份账本；WorkIntent计时与job计时分开。设计签定不记运行PASS |
| **CP1 · H5：正常旅程已成品化接通** | 可持久启动、库存/分配/任务、租约/续租/释放/到期、Owner/幂等、正常执行模型；状态重载 | 六区正式布局和共用组件；正常提交到结算的实际操作；基线插件；真实查询与时间线；两阶段部分失败交互 | 两人换角色操作；32并发争最后资源与重复申请；刷新后仍一致；推进时钟到期；一次allocation成功但job失败不重复借卡；真实终态显示资源仍保留或已按授权释放 |
| **CP2 · H10：三角色动态服务完整** | 全部测试控制、贡献者写扩展、ready/failed/timeout、回收/无替代等待/恢复、两类预算、节点状态和代次；CPU参考适配第一条实际路径 | 普通贡献者真实开放/收回，任务连续性与决策解释，候选策略接入，完整场景运行器；六区全部读实际数据 | 21操作均有实际记录；六组回收分支真实闭环；普通贡献者无测试密钥也可归还自有资源且不能动他人设备；大步clock不跳事件；失败不假恢复；第一次CPU保存—停止—恢复到结果 |

| **CP4 · H21：发布候选与独立挑战** | 从干净目录/目标环境启动，所有必做分支与并发检查；规模/延迟实测；部署与迁移材料 | 陌生输入演示、完整UI检查、实验图表和证据索引；交叉HTTP核验；完整视频预演 | 以README换人部署；核心可靠性无已知违例；完成自定50,000命令/规模目标或明确记录未达项；每个图表追到run；六个用户任务互测；构建、场景、模型、视频候选版本一致 |

### 每个节点都检查“用户做成了什么”

CP1不是后台能启动、前端有六张静态图；它要有真实借用和结果结算。CP2不是状态码全填上；它要有正常贡献者收回与用户真实等待/恢复。CP3不是写出策略公式；它要有合理基线、个体差值和可复验结果。CP4不是压缩包存在；它要能由另一人从干净环境运行。

节点未达目标时写清：失败请求/事件、责任模块、局部修复范围、下一次自动检查。完整产品目标不悄悄下调，也不把“部分实现”改名“完整”。

## 4. 每个连续工作区块的追求

### H0—H1：设计定格

共享最终故事、接口、状态与视觉；不在这段寻找十套框架。A确定事务和语义可替换处，B确定产品信息架构和同条件评估。最终目录、路由归属与模型身份一次确认。

### H1—H5：两条正式主干并行长出来

A持续完成从请求到持有再到归还的正常路径和持久性；B持续完成正式界面、查询、正常工作流与基线策略。UI设计、空态/错误反馈、结算卡此时就进入最终组件，后面只补真实分支和细节。

### H5—H10：最难的事件关系与体验一起完成

A连续处理通知、到期、失败、恢复和真实参考执行；B连续处理用户如何理解这些状态、策略如何使用当时信息、实验如何产生同条件输入。A补一项事件，B不需要临时重画页面，只消费既定事件结构。

### H10—H16：深度攻坚

A负责正确性、持久化与执行边界的攻击；B负责候选策略、解释与效果的攻击。大规模实验和自动回归作为后台批任务运行，两人继续各自主线。调度公式遭反例推翻时只替换策略实现，不能破坏接口、产品和已成立的证据。

### H16—H21：把已有能力做到发布品质

A完成性能、部署、跨模块不变量和执行恢复；B完成视觉一致性、难用交互、完整证据浏览与演示。双方互换操作，专挑自己没写的模块和未见组合。这个阶段仍可完成已承诺能力，不因钟点直接取消目标；新增不相关平台/市场/框架不进入主干。

### H21—H24：同一构建完成交付

B在独立实例录制，A在另一个目录核验同一候选包。若修复改变了视频中的行为，更新受影响片段与构建标识。两人分别提交自己的说明，不让一人最后替整个系统编写解释。

## 5. 自动融合，人工只处理重要分歧

每次合入自动运行：合同类型检查、模块自测、公共接口回归、资源不变量、前端构建和关键路径冒烟。测试失败生成短回执：构建、请求、逻辑时刻、revision、事件片段、预期与实际。

平时只异步发送这类回执和接口就绪通知，不让另一人解释整段日志。固定节点再集中看产品。无跨边界阻断的问题由所属Owner处理，不能把全部失败都升级为二人会议。

仅以下情况立即打断：已提交状态可能超卖/越权/污染另一实例，公共契约或共享schema发生不兼容变化，另一人的所有主线都被同一个缺口阻塞。普通样式问题、单策略劣化、非关键文案留到各自工作或下个checkpoint。

## 6. 遇到失败仍保持正向开发

| 失败 | 局部处理 | 另一人继续做什么 |
|---|---|---|
| 账本/代次错误 | A保留最小失败历史，修唯一提交或事件边界，加入永久回归 | B继续查询组件、策略纯函数、健康路径和实验分析，不直接改状态补洞 |
| 快照/路由合同偏差 | 所属Owner修适配；只增可选字段或做显式版本迁移 | 另一方按冻结合同继续，不整套重写 |
| 候选策略无收益 | B核对信息、代理信号和反例；比较B2及消融，替换局部决定 | A继续执行正确性、持久化和性能，不等待“算法研究结束” |
| 策略耗时或计划失效 | A拒绝过期计划，按已声明后备策略维持服务；B在隔离入口优化 | 正式产品仍能使用，页面显示实际策略，不能混报成绩 |
| 解释与实际决定不一致 | B修decision投影；A提供当次提交版本和事件 | 决策记录保留，禁止用事后文案遮盖 |
| 崩溃后CPU进程仍运行 | A核对执行代次、监督进程与停止确认；不重复启动第二份执行 | B完善恢复等待/执行未确认的诚实显示 |
| 自定规模/延迟未达 | 剖析索引、快照和批处理成本；保持正确性后优化 | 同步完成产品操作和结果证据，不关闭检查换数字 |
| 临近截止有未达目标 | 标记缺口和影响，集中修阻断、保留实际完成能力与负结果 | 完成已存在能力的演示与材料；不宣布未达目标通过 |

后备策略是正式架构的容错能力，不是回到另一个低规格原型。调用链、用户体验、对象身份和证据体系保持一致。

## 7. 执行时的两个重要约束

**高目标与可信交付同时保持。** 未达到15%收益、规模或响应目标，可以是有价值的研究结果；不得以修改分母、删除困难seed、虚报实GPU或偷偷换基线“达成”。基础可靠性和正式必做项有缺口则明确列出，不能被精美界面掩盖。

**可并行冲刺，不以框架数量定义高度。** 真实K8s/KWOK、GPU适配、自动反例缩减使用已经留出的接口开展。它们若证明额外价值就进入成品；已有CPU参考执行与持久化是正式目标，不再拖到有空才做。

所有定量标准只维护在01和03，阶段记录引用同一目标ID。旧方案与分工研究笔记保留供追溯，不再形成并行的第二套验收口径。
