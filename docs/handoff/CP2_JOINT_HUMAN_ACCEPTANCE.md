# CP2 联合验收：A / B 操作卡

当前是 **CP2 技术复核完成后的人工验收入口**，不是 CP3 放行记录。以本轮验收报告中的提交号为准；A、B 都要实际完成以下操作，再交换记录。此前 CP1 的通过不替代本轮。

## 打开与准备

A 使用已启动的本机实例；B 在自己的仓库保留现有分支，执行 `git fetch origin`，然后 `git worktree add ../campus-fabric-cp2-review origin/review/cp2-acceptance`。进入新目录，按 [启动指引](CP2_JOINT_QUICKSTART.md) 执行 `make setup` 和 `uv run python scripts/cp2_joint_session.py start`。不要向另一分支覆盖文件。

| 入口 | 打开地址 | 导入文件 |
|---|---|---|
| 逻辑模拟 | http://127.0.0.1:15180 | `runtime/cp2-joint/logical/client-identities.json` |
| 真实 CPU | http://127.0.0.1:15181 | `runtime/cp2-joint/cpu/client-identities.json` |

`127.0.0.1` 是各自电脑。身份文件只在本机使用，不发给对方。选择 `alice` 为研究者、`supplier` 为贡献者、`admin` 为管理员；`bob` 用于权限检查。左侧切换页面不得改变身份。整页刷新后需要重新导入身份文件，这是当前明确行为。

## 1. 逻辑模式：回收、等待、恢复、结算

1. **alice / 运行工作台**：默认资源，GPU 型号填 `A10`；中断处理选 `checkpoint`，租约 300 秒，成功后自动归还，其他默认。提交并查询工作，等到出现运行中的任务与执行 #1。记录工作 ID、任务 ID、租约截止。
2. **supplier / 资源与贡献**：勾选两张 A10 物理卡；通知期 `3` 秒、收回占用 `20` 秒，发送通知。
3. **alice / 任务连续性**：查询同一工作，刷新后点击“报告保存 ready”。此模式只能显示“收到报告、未核验、未接续”，不能冒充真实保存。
4. **admin / 系统验收**：推进 `3` 秒。回 alice 刷新并点“恢复这项工作”。这时两卡尚不可用，应进入等待；重启预算仍未消耗。截图。
5. **admin** 再推进 `20` 秒。回 alice 刷新，应出现同一任务的执行 #2，恢复预算使用 1 次；工作 ID、任务 ID、原租约截止不变。
6. **admin** 再推进 `10` 秒。回 alice 刷新，工作完成、租约已释放。展开关联决策并核对实际事件；整页刷新、重新导入 alice 后还能查到同一记录。

## 2. CPU 模式：真实保存与结果

先开两个 CPU 标签页，分别导入 CPU 身份文件，选 alice 和 supplier，避免来回登录耽误时间。

1. alice 按上面同样参数提交工作，等任务确实运行。固定参考程序约 50 秒完成，**正在运行时**立即在 supplier 页对两张 A10 发 `3 / 20` 秒通知。
2. alice 在任务连续性刷新：应看到实际保存点“已核验”。此模式由执行器自动保存，不应提供人工 ready 按钮。
3. 等原执行停止后，点“恢复这项工作”。资源未返回时可显示等待；之后刷新，确认执行 #2 与“已接续”。工作/任务 ID、租约截止不变，恢复预算 1 次。
4. 等工作完成、租约已释放，下载真实结果。文件中 `state.step` 应为 `1000000`，`state.value` 应精确为 `16159431991146531633`。保留下载文件及结果截图。若来不及收回而已完成，另建一项工作重试，不能把无中断完成记作恢复成功。

CPU 是实际运行的固定整数参考程序；GPU 库存仍为模拟，不执行表单中的镜像/命令。此处验证保存、停止与接续，不代表真实 GPU 训练性能。

## 3. 权限、实验与六工作区

- 两种模式均切为 **bob**，在任务连续性直接输入 alice 工作 ID并查询，应返回 **404**；仅列表筛选无匹配不够。
- **bob / 资源与贡献** 不得出现 supplier 卡片的可操作回收选择。
- **admin / 事件与实验**：逻辑实例选择目录中一个场景与 `P`，运行隔离实验；查询直到完成，下载固定输入及汇总。应有真实 run ID，且主实例逻辑时间、工作/租约不因实验而改变。
- **系统验收**：CPU 实例不得出现手动推进时钟；缺少双人证明的 CP2 联合状态不得显示通过。所有六个工作区都需打开并核对真实数据。
