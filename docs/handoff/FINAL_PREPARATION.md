## 架构改了什么，仍缺什么

原瓶颈主要是每条普通写入都读取、复制、比较并序列化整份历史。本轮按实体读取和写回，增量更新状态根；活动工作、待发命令和局部详情通过索引读取。保留 SQLite FULL 持久化、同库原子资源/事件/回执提交、旧日志与独立重放。没有清历史、改变租约语义或跳过权限来换速度。

这与调度策略 P/B2 的 R=1.00 完全不同。当前策略结果未改善，没有重跑 125 组，也没有把新的数据库开销算成调度收益。

正式并发试验另发现无故障请求仍在事件循环内争抢故障消费写锁。`b19acae` 已独立补修：只读快照确认无活动规则，存在规则时进入写事务重查并消费；阻塞核验移出事件循环。49 项定向回归通过，恢复旧路径的两项反证均抓到原缺陷；另一代理只读审查无阻塞问题。普通业务写仍是单写，不能只修事件循环就保证原 p95 门槛满足。设计和线性化边界见 [请求隔离](../architecture/REQUEST_ISOLATION.md)，验证说明见 [观察记录](../../evidence/request-isolation/validation.md)。该观察记录没有伪装成未保存的原始终端日志。

阶段计时随后直接观察到写锁长等待和后到越过，持锁业务中库存构造约占三分之二。`5f25604` 将校验改为事务实际资源输入变化驱动，对受影响节点检查全部现有声明；拓扑、隔离、未知结构保守全量，启动建立完整语义基线。builtin 首次匹配按原顺序逐节点求值，128 节点定向例只解码选中节点，原有 whole/MIG 轨迹由冻结旧实现对照。每个 SQLiteStore 内部增加至多64票的 FIFO，跨进程仍由 SQLite 授权，不宣称全局公平。API、权限、原租约、FULL 持久化与单库原子性保持。

详见 [事先协议](../architecture/RESOURCE_LOCALITY_PROTOCOL.md)、[写入准入](../architecture/WRITER_ADMISSION.md) 和 [独立资源审查](../../evidence/resource-locality/review.md)。当前5f25604的源摘要为 `4f4dd64f0f473a96751a60e37b74bd1cc0f3eab49d3658a16a63fdcd894c1c4d`，331 个源文件；汇总提交只增加交付资料，不能将运行回执的原 Git 身份改成汇总 HEAD。

## 路演已经确定的方向

以“可收回的算力，可核验的接续”为中心，让评委选择合法收回时机和继续/取消结局。主讲追踪同一工作，证明原进程停止、新进程实际加载保存点、输出可核对和资源真实归还。总览与转场帮助理解这条过程，不能成为替代系统价值的高潮。

目前真正缺少的不是再一张宣传页，而是最终同构建的完整事实链，以及一项预先声明的“合法接续/从零恢复”的成本对照。后者是主张实际收益的必要证据，不是靠演讲或动效可以省掉的环节。没有后者就不宣传节省比例；没有最终质量证据就不宣布 CP4 放行。
