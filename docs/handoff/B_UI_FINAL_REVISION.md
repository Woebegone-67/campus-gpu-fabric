# 给 B：本轮按交互终稿交付

2026-11-15，用户实际试用后的最新要求。最新接手分支：`integration/ui-final-20261115`（在 B 的 `4d25467` 上完成联合对齐）。本文件覆盖此前以“设计交接/开发样例”为目标的界面建议；技术事实与权限约束仍保留在系统实现和项目文档中。

**这不是再做一轮皮肤优化。需要从头到尾审查最终用户会看到、读到、点击到的全部内容，以最终版作为交付标准。** 用户给出的文字、按钮和板块只是例子，不是检查范围。不能只删几个被点名的地方就交付。

## 1. 当前问题的根源

现在的页面仍像把研发说明书拆成卡片：每个标题后重复解释，每个按钮旁提醒边界，每个状态后再次申明后端权威。标题、眉题、描述、帮助文字、范围说明、空状态堆叠，却没有相应增加可操作信息。

另一个问题是所有模块都争取成为完整卡片。首页同时有宣传句、入口按钮、提醒、进行中、设备、已结束，导航又在侧栏和页头重复。用户需要先阅读系统的组织方式，才能找到自己的工作。

本轮原则：**先删掉无用的内容和入口，再重排必要内容，最后调动画。** 不以改写一遍说明、换小字号、折叠成大量提示图标代替删除；不再新增口号、模块眉题或装饰卡片来“补设计感”。

## 2. 全站文案与入口删减（P0，B）

需要逐个检查 JSX 中的 `description`、`helper`、`small`、`eyebrow`、空状态和错误提示，而不是批量删类名。用户的要求是删除堆砌的解释性与防御性说明；字段名称、必要单位、真实错误和操作结果仍应清楚。

| 现在的问题 | 终稿处理 |
|---|---|
| 每个小模块都用小字重新解释标题 | 删除，标题自身说清用途；不再配套一段概述 |
| “服务端为准”“不代表通过”“当前快照只作提示”等反复申明 | 从日常产品页面删除；开发/验收边界留在项目文档 |
| 页头“暂停背景动效”“显示设置”常驻 | 移出页头；低频偏好合并到一个账户菜单内的偏好入口，减少动效自动遵循系统设置 |
| 左下“临时共享 · 持续接续”等口号 | 删除；侧栏只保留导航和确有用处的状态/账户入口 |
| “让计算，继续发生”“从这里看见进展……”等首页宣传文案 | 删除；将首屏空间留给用户当前需要处理的内容 |
| 英文眉题和中文标题表达同一件事 | 保留一层标题，不用双语眉题制造层级 |
| CP 编号、HTTP 状态码、请求 ID、版本、逻辑时刻、内部阶段名进入普通操作区 | 从普通主路径移走；排障时在统一的详细记录入口查，不在每个模块旁解释 |
| 多处说明“最多 25/50 项”“不能代表全部”等 | 用一次简洁范围标记，如“最近 25 项”；数据不全时显示短状态与刷新入口，不写段落 |
| 解释提醒排序算法、未记录时间的排序位置 | 删除；排序应直接工作，不让用户读算法 |
| 空状态介绍未来功能、技术原因、开发限制 | 改为当前事实和一个有效动作；无需动作时只留一句状态，不放整块占位卡 |
| 所有请求成功都产生大型回执卡 | 用靠近操作的简短反馈；具体业务结果留在对象状态中，技术回执可从详情菜单查 |

不要删除真正影响用户操作的消息。例：“名称不能为空”“连接中断 · 重试”“任务已停止”“资源归还中”有明确作用；“按钮仅表示当前快照可用、提交后仍复查权限状态预算”属于应删除的实现说明。

减少说明不等于制造虚假状态。没有进度数据就不要画百分比；已加载 25 条就不要标成“全部”；真实 CPU 参考执行不能包装成真实 GPU 训练。环境类型可在统一实例信息中用短标签说明一次，正常模块不反复展开。测试和比赛边界写在交付文件中，不让普通页面充当免责声明。

### 用户点名的供给板块

整块移除 `CPU 参考实例供给`，包括：

> 此实例的库存由启动配置载入。
>
> 在线登记供给需要准确的逻辑时刻；CPU 参考实例的时钟持续前进，因此这里不提供手工登记。请在逻辑模拟实例登记供给。
>
> 已有自有 GPU 的收回通知仍可在上方提交。

最终页面展示的是“我的设备”和当前可以执行的管理操作。不能登记时，不展示一套无法完成的登记流程再用技术段落解释。将确属部署管理的库存配置放在管理员配置路径；普通账户继续管理自己已有的供给。

如最终产品主张“用户可自助接入新设备”，但当前后端没有这项能力，B 需明确交回一个后端缺口，A 负责接口和生命周期。不能把能力缺口美化成可用流程，也不能把删除说明当作这项能力已经实现。当前同账户双能力已支持使用计算、查看和收回自己的供给；这不等于完整硬件接入向导已完成。

## 3. 工作命名（P0，B 设计与界面；A 后端支撑）

用户不能一直靠 UUID 区分工作。新建表单第一项应为“工作名称”；总览、提醒、列表、详情、事件上下文统一显示该名称，技术 ID 仅用于复制、排障和原有深链接。

**本轮联合对齐已实现持久化命名。** `WorkIntentRegistration` 和 `WorkIntent` 已有 `display_name`，列表、总览、详情、关联事件和决策上下文已接通；旧数据仍兼容。B 后续调整布局请保留接口及以下语义，具体证据见 [联合对齐](UI_FINAL_ALIGNMENT_20261115.md)。

已落地的前后端契约：

- `/x/v1/work-intents` 扩展登记和查询模型增加可选 `display_name`；1–80 字符，去除首尾空白。新 UI 要求填写，旧客户端/旧数据允许缺省。
- 名称可重复，不作为身份、权限、幂等键或 URL。保留原 `intent_id`。
- 同一次登记重试保留原名称和输入；中断、接续及租约处理不改变名称。
- 持久化并出现在列表和详情投影；刷新、重启和另一台设备重新登录后仍一致。旧记录使用简洁的“未命名工作 · 短编号”回退。
- 列表筛选支持名称；如果后端只有当前页数据，界面不承诺全局搜索。
- 暂不扩展为项目管理或复杂标签系统。重命名若本轮确需支持，单列一个有权限校验的元数据更新动作，不借用重新登记制造新工作。
- 只修改产品扩展契约并重新生成类型，不改冻结的官方 API；A 补持久化、旧数据兼容、重试一致性和越权检查，B 补名称输入、验证、显示与检索交互。

交付必须包含新名称完整跨页面、刷新与服务重启后的实际证据。不能通过假数据终稿验收。

## 4. 首页重新组织（P0，B）

首页是“现在与我有关的事”，不再是产品介绍页或缩小版工作台。不要强行固定四五块同等大小的卡片。

建议从以下结构开始，再用真实不同状态验证：

1. **需要处理**：有事情才突出显示。每项只保留工作名称、发生的事、必要时间和一个下一步动作。点名称和动作不要制造两套意义相同的入口。最多首屏展示三项，其余通过“查看全部”展开。
2. **正在进行**：简洁列表，展示名称、状态和可以获得的进度信息。等待、运行、中断应容易区分；同一工作若已经在需要处理中突出，不再以同等视觉权重重复出现。
3. **自己的供给**：确有设备时提供紧凑摘要和管理入口；没有设备时不要放一张大空卡教育用户如何成为贡献者。用户仍可从工作台“我的设备”进入相关路径。
4. **最近结果**：低优先级的少量记录或一个入口。有新完成结果时才突出提示，不能与进行中列表争首屏。

没有待处理事项时，轻量显示“暂无待处理事项”或直接收起该区；没有任何工作时，一个“新建工作”入口足够，不要出现三个相似空状态。管理员首页按管理职责组织，不能复用一套充满个人空列表的首页。

一次刷新应有一个明确入口与简短更新时间。数据暂时不一致或部分不可用时，保留仍可用内容并局部标记；不要让普通用户读快照世代、租约关联规则和排序方法。

背景只承担氛围作用：降低正文附近亮点密度和对比，禁止文字所在表面透出干扰阅读的点网。不能为了展示背景把业务内容往下推。艺术层在进入工作台时退出。

## 5. 详情与新建主路径（P0，B）

本轮真实截图 `evidence/ui-joint/20261115/live-02/completed-released.png` 显示：查找框和成功回执占据了大半首屏，结果/下载在下方。这需要作为终稿问题修正。

- 从首页或列表进入某项工作，第一屏直接出现名称、状态、下一步和必要结果，不先要求再读一遍“查找工作”。“查找另一项工作”放到次级入口；保留现有深链接。
- 任务完成后，结果查看/下载是主动作；仍占资源时，归还动作应与占用状态相邻。完成、失败、取消各自有清楚结局，不靠下方长解释区分。
- 可恢复时主动作明确为恢复，恢复请求后区分等待资源和实际接续；正常等待不向用户显示一串灰掉的内部重试按钮。
- 只显示此刻有意义的操作。对高影响操作提供一句具体确认，例如“收回这两张设备，将中断正在使用它们的工作”；不采用通用“请核对权限、状态与预算”。
- 时间线只保留关键事件与发生时间；技术事件名、JSON、执行代次内部结构进详细记录。真实接续证据仍可查，但不应变成默认操作页的主体。
- 新建工作优先是名称、计算需求和运行方式。高级资源参数进入一个有组织的高级区域；镜像与命令当前不执行，就不能摆成看似必需的执行配置，让用户误以为上传了自己的程序。
- 新建入口点击后直接抵达可填写的表单，焦点落在名称；提交成功进入该工作的详情或给出唯一明确的继续动作，不再留下多块回执要求用户猜下一步。

## 6. 账户连接（P1，B 界面；A 决定认证能力演进）

身份与权限验证需要保留，**本地文件导入不是产品本质要求**。它是现有本地部署的开发入口，不应作为终稿的主要产品印象。

本轮在不更换认证后端的范围内，B 可以：

- 用简洁的“连接账户”入口完成一次连接；普通已连接界面只显示账户按钮。
- 将已有的接入凭据输入整理成清楚的一步表单，把文件导入作为备用/高级方式；别把文件、Owner、token、选择器四套控制同时铺开。
- 未连接、验证中、已连接、连接失效有清楚而短的状态；已有工作仍留在服务端。刷新后需要重新连接属于当前机制，应在连接处一次说明，不在业务区反复提醒。
- 不能提供“选 Alice/Bob 就登入”的无验证角色切换，也不能把共享开发 token 塞进前端包。名字和角色标签不授予权限。
- 不为了省一步而未经设计把 token 永久放入浏览器本地存储。完整密码/校园 SSO/安全持久会话需要 A 后端支持，不能靠 UI 假登录冒充。

如果 B 认为终稿必须包含持久登录，则作为明确前后端协作项提出；当前分支没有声称实现正式登录系统。

## 7. 操作顺滑程度（P1，B）

顺滑首先是操作连续、位置稳定、状态及时，其次才是动效。

- 将导航、选中、悬停、按下、提交中和完成反馈统一；按钮按下立即有响应，等待实际返回后才显示业务成功。
- 普通按钮视觉反馈约 100–160ms，面板展开约 160–220ms，空间转场约 220–320ms，作为调试起点而非机械统一时长。优先 opacity/transform，避免全页高度跳动、弹簧反复回弹和每张卡逐次入场。
- 刷新不清空整页，不因按钮文案变化让表格或操作条移动；初次加载和已有内容的刷新分开处理。
- 表单错误就在字段附近；失败保留输入；成功反馈简短且不会压低主体。提交中防止重复业务写入，不能用假成功换流畅。
- 返回列表保留原筛选和位置；总览/工作台切换保留草稿。键盘焦点跟随当前可见内容，不能停在隐藏页面。
- 双指横滑保留可见导航作为同等入口。只对已验证安全的区域接管手势；需实机验证惯性回弹、纵向滚动、表格横滚、输入和弹层、浏览器后退。不要为了“更丝滑”取消这些边界后直接宣布完成。
- 用户不需要在右上角常驻两个动效/设置按钮。系统减少动效时自动退化，低频偏好统一放入账户菜单。

从每一个可见入口走到结局，包括返回、取消、关闭、失败重试和深链接。检查按钮是否确有用、文案是否重复、下一步是否清楚；不仅查看静态首页截图。

## 9. 交付与验收方式

优先顺序：全站删减 → 工作名称与依赖对齐 → 首页层级 → 工作主路径 → 账户入口 → 交互细化 → 全面走查。先冻结信息结构，再做精修，不继续增加功能或口号填空。

B 应交回：

1. 代码提交及所依赖后端提交。逐项标记本清单已完成、仍阻塞和原因，不将“改了文字”当作“完整流程实现”。
2. 逐屏审查记录：每条路径、角色、状态、实际浏览器/设备、发现的问题及结果。未验证的状态明确留空。
3. 一段连续实录：连接 → 首页 → 命名并创建工作 → 运行 → 合法收回 → 接续 → 结果与归还；另附失败/取消结局。需要双方真人交叉的环节写明操作者。
4. 实际桌面和窄窗口截图，覆盖空/繁忙/异常状态；Chrome 和 Safari 的物理触控板记录，以及键盘和减少动效检查。
5. 真正的剩余后端需求单，至少明确命名持久化；如选择自助供给接入或正式登录，定义具体请求/响应和流程缺口，交给 A 实现，不以解释板块代替。

本轮只跑改动对应的必要回归和浏览器关键链，不再每改一次样式就重复 125 组策略实验。联合分支已有的真实 CPU 下载、权限与恢复记录用于对照，最终新交互仍需自己实际走通，不能沿用旧截图当终稿。

**终稿判定：普通用户无需阅读实现解释，就能看清当前状态并完成下一步；每个可见入口有完整结局，关键操作有真实后端支持。任何未支撑的关键路径仍是未完成，不以“演示可以用”放行。**
