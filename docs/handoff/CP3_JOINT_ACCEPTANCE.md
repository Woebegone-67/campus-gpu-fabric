## 身份与记录方法

先点击右上角“当前身份：alice”展开身份面板，再在“导入本地身份文件”选择对应实例的文件；选好身份后点“应用身份”，核对右上角名字。

- `alice`：提交工作、查结果、恢复工作。
- `supplier`：收回自己贡献的两张 A10 卡。
- `admin`：逻辑时钟、封存策略报告、隔离实验。
- `bob`：检查是否能越权查看 alice 的工作。

文件只在浏览器内解析。不要把身份文件、令牌、数据库或原始日志发给对方。整页刷新后重新导入身份文件即可；记录应仍能从服务端查到。身份切换后先检查右上角，不凭之前页面判断。

每人建一个记录文件夹，按下面的名字保存截图与下载；同时记下每项工作的完整 ID。不要只截列表“没有匹配项”，权限验收要直接查询工作详情并看到 HTTP 404。

## 旅程一：成功、失败与租约归还（逻辑页面）

### 1A. 完成工作不等于归还资源

1. `alice` → **运行工作台**。GPU 型号 `A10`，GPU 数量 `1`，租约 `300` 秒；中断处理选“尽力运行”，租约结算选 **保留租约，手动归还**。其他默认，提交一项新工作，记 ID 为 `W1`。
2. 到 **任务连续性** 查询 `W1`，确认任务已开始。记下租约 ID。
3. 切 `admin` → **系统验收**，推进逻辑时间 `10` 秒。切回 `alice` → **任务连续性** 查询 `W1`。
4. “结果与结算”应显示工作已完成，但租约仍持有资源，提示需要归还。保存 `01-completed-held.png`。逻辑模拟不应产生“真实 CPU 结果”下载。
5. 点击 **释放租约**，刷新，确认租约已释放、工作仍为完成。保存 `02-completed-released.png`。整页刷新，重新导入 alice，再查同一个 `W1`，结果必须仍在。

### 1B. 失败必须如实展示

1. 新建 `W2`：资源同上，中断处理“尽力运行”，结算选 **结束后申请自动归还**。确认正在运行。
2. 切 `supplier` → **资源与贡献**，勾选其两张 A10 卡，通知期 `3` 秒、收回占用 `20` 秒，发送通知。
3. 切 `admin` 推进 `3` 秒，再切 `alice` 查询 `W2`。
4. 应显示失败或被驱逐的终态及原因，租约不再占用资源；不能显示成功或虚假的已接续。查看关联事件核对原因，保存 `03-failed-settled.png`。
5. 切 `admin` 再推进 `20` 秒，让贡献卡可再次使用。若其他工作占用，先核对它的租约，勿直接重置实例。

## 旅程二：保存报告、工件核验、实际接续

### 2A. 逻辑 ready 不能变成真实保存

1. `alice` 新建 `W3`，GPU 型号 `A10`，中断处理 **保存点恢复**，结算 **成功后申请自动归还**。确认运行。
2. `supplier` 对两张 A10 发送 `3 / 20` 秒收回通知。
3. **先回 alice 查询 W3，点击“报告保存 ready”，确认已收到报告，再推进时钟。** 这一步不能遗漏；不要在 ready 之前推进 3 秒。
4. `admin` 推进 `3` 秒；alice 点击 **恢复这项工作**。资源不可用时应等待，恢复预算不增加，保存 `04-logical-wait.png`。
5. `admin` 推进 `20` 秒。alice 刷新，应出现执行 #2、恢复预算使用一次；工作 ID、任务 ID和原租约截止保持不变。
6. `admin` 推进 `10` 秒。alice 刷新，应完成且释放。保存 `05-logical-complete.png`。“收到 ready 报告”不能自动变成“工件已核验 / 保存点已接续”。

### 2B. 真实 CPU 工件必须真正用于接续

这里改用 **15183 CPU 页面及 CPU 身份文件**。先开两个标签页，分别使用 alice、supplier，避免来回切换错过运行期。

1. alice 新建 `W4`：A10、保存点恢复、成功后申请自动归还。固定参考程序约 50 秒完成；看到运行后立即通知 supplier 操作。
2. supplier 对两张 A10 发 `3 / 20` 秒通知。CPU 按真实时间运行，**不需要也不应手动推进时钟，不手点 ready**。
3. alice → **任务连续性** 查询 `W4`，刷新至保存点“已核验”，下载已核验保存点，保存 `06-cpu-verified.png`。
4. 原执行停止后点击 **恢复这项工作**。等资源回来后刷新，确认执行 #2、保存点“已接续”，保存 `07-cpu-applied.png`。同一工作/任务 ID、原租约截止保持不变，恢复预算只增加一次。
5. 完成后，检查“结果与结算”为成功，租约已释放，保存 `08-cpu-result.png`。点击 **查看真实结果** 与 **下载真实结果**，文件应给出 `state.step = 1000000`、`state.value = 16159431991146531633`，不应显示成科学计数法后丢失精度。
6. 若工作在收回前就完成，这仅是普通完成，不能记作恢复成功。新建一项重做即可，旧记录保留。

## 旅程三：解释、权限与跨页面一致性

1. alice 查询 `W4`，展开关联决策和历史；查看分配资源、候选范围、提交结果，确认它们指向同一任务和相应执行。保存 `09-decision.png`。
2. 以 alice 打开六个工作区：运行工作台、资源与贡献、任务连续性、决策解释、事件与实验、系统验收。切换工作区后身份不能改变。
3. CPU 页面换成 bob，在任务连续性**直接输入 `W4` 完整 ID并查询**，应返回 HTTP **404**。保存 `10-bob-404.png`。bob 不应能下载 alice 的 CPU 工件或对 supplier 的卡发送收回通知；管理员专用内容不能因修改 Owner 字样而开放。
4. 切回 alice，整页刷新、重新导入身份，仍能查询 `W4` 和展开决策。记录“刷新后仍可查”。
5. CPU 页面切为 admin，进入系统验收，连续刷新管理员总览十次，应能正常读取，不出现此前的随机 HTTP 409。

## 旅程四：CP3 封存实验与运营隔离

使用 **15182 逻辑页面**，这样检查前后的逻辑时间不会自动增长。

1. 先用 admin 记录当前逻辑时间、已有工作与租约数。保存 `11-before-experiment.png`。
2. **事件与实验** → 找到 **CP3 策略配对验证**。这块读取已封存的正式实验；与旁边可运行的研发样例不同。
3. 检查真实的总体比值 R、目标是否达到、完整性与覆盖缺口。**如报告显示未达目标或覆盖不完整，页面应原样展示，不能变绿或隐去缺口。** 人工验收通过表示页面忠实，不表示算法门槛通过。
4. 下载 **冻结协议** 和 **完整配对报告**。任选一个场景族、一项策略，展开 **查看下载项**，下载输入、汇总、决策和运行元数据。表格显示场景、种子、策略；运行元数据的 `run_id` 应与下载文件名和冻结清单对应。保存 `12-policy-report.png`，保留下载文件。
5. 在研发样例区域运行一个隔离实验（任一目录场景、P、种子 0），等完成后下载输入与汇总并记录 run ID。
6. 回到运营工作区，刷新并核对逻辑时间、工作/租约数量与第 1 步相同；没有自动新增运营工作。保存 `13-after-experiment.png`。请勿同时手动推进主时钟。
7. 切为 bob，明确点击 **管理员 · 读取 CP3 报告**，读取应被拒绝，不应继续显示旧管理员的报告或下载内容。只看到空面板不能代替此检查。
