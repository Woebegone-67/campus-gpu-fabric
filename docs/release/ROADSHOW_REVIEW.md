# 五分钟路演独立评审

2026-11-15。评审对象为本目录 `ROADSHOW_5MIN.md`，依据 `spec/official/challenge.md` 的 55/45 标准、`MORNING_GUIDE.md`、本轮浏览器记录和 `docs/research/FINAL_LOSS_ACCOUNTING.md`。本次只评审，不修改主稿，不替代真人计时。

## 判断

新稿已经有一条可讲清的主线：贡献者收回设备，使用者保住计算，在原约束下完成同一项工作。它比页面巡游有辨识度，也符合题目方向 B。最强的一幕应是**设备已经归还，原工作的进度仍在第二次执行中继续**，随后看到可下载的完整结果。

目前能证明的是完整可操作的系统，以及特定参考程序中保存接续的价值。尚不能证明一种优于正确简单基线的新调度算法。题目第 3.3 节已经要求通知、保存、恢复、等待和失败处理，因此不能只把这段基础流程换一个名字，就认为获得了核心创新 20 分。第 4 节方向 B 允许深入研究双向权利的取舍，方向 F 允许真实工程能力；本作品最可信的竞争力是这两者的结合及可复算的结果，机制原创性仍是评分中的弱项。

优先改以下三处。其余内容无需继续堆叠。

## 1. 强基线必须进入主图，不能只放在旁注

主稿 59–65 行讲三臂，但 81–86 行的主表只列冷启动与接续。最容易被评委追问的是：“你们只把 checkpoint 和没有 checkpoint 相比，为什么称为创新？”如果第三臂的数字需要打开另一份报告才能看到，这个追问成立。

建议主图只展示中期这一行场景，三种方法并列，避免挤入所有实验细节：

| 同一中期中断条件 | 重复计算 | 通知后多久确认停止 |
|---|---:|---:|
| 直接停止、从零重启 | 505 万步 | 10 ms |
| 立即保存、接续 | 5 万步 | 20 ms |
| 固定截止前保存，先完成则直接结束 | 0 步 | 558 ms |

图下注明：真实 CPU 参考程序；三条单次执行观测；通知窗口均为 1 秒；均未观测到逾期。这里的停止时间是执行器进程确认，不是 GPU 资源的测量。固定截止基线合法使用了贡献者允许的通知期，不能把它说成侵害收回权；更早归还是否更有价值，取决于贡献者的实际需要。

同屏再用一行交代全分母：四个固定场景，接续完成 3/4，另外两臂 4/4；保存失败例没有删除。这个样本不能估计真实平台完成率，强基线的故障例在保存前自然结束，也没有证明其抗保存故障能力。详细零进度、晚期与失败账目留在备份。

**可直接替换 3:00 段的讲述：**

> 保住进度，究竟值多少？同一 CPU 程序中期中断，从零重启重复计算 505 万步；立即保存接续只重复 5 万步，约 20 毫秒确认停止。我们也比较了更强的办法：利用允许的一秒通知期继续计算，到截止前才保存。这次它直接完成，零重算，约 558 毫秒确认停止。
>
> 所以这里有两本账：使用者少重算多少，贡献者多等多久。四个固定场景里，接续完成三个，保存失败的那一个也保留。我们交付的是能执行、能核算这两本账的系统；这组结果没有证明新的算法胜过简单基线。

数字只用于固定实验图。现场工作要展示现场自己的起点，不能把 505 万步贴到另一个任务上。第三臂当前在研究工具中实际执行，尚未接入普通产品操作，不能演示成已经上线的选项。主稿中的“同程序三臂”成立；“产品有三种可选策略”不成立。

## 2. 把 50 秒“绿灯语义”改成双向结果的记忆画面

主稿 49–55 行花一整段解释“几个成功不能混成一个成功”，并串入幂等、迟到回调等条件。内容正确，但听众需要先理解使用者得到什么，再理解为什么可信。现在这段容易把项目重新讲成审计系统。

主画面应保留同一个工作名称，呈现两条具体事实：贡献者这边进程已退出、设备已收回；使用者这边第二次执行从本次核验的保存点起步，最后完成。不要新造百分比、舞台计数器或动画进度。现有详情页面和真实记录足够，展示时明确指出对应位置。

**可直接替换 2:10 段的讲述：**

> 现在看双方各自得到了什么。贡献者这边，原进程已经退出，设备可以收回。使用者这边，同一项工作没有从零开始：第二次执行实际加载了刚才的保存点，接着完成剩余计算。**借的是设备，留下的是进度。**
>
> 这靠两个边界保证：停止确认后才释放资源，恢复仍沿用原租约期限。最终文件可以下载，我们还用独立计算核对完整结果。

其中“最终文件”应在当前现场工作确实完成时指向当前记录。尚未完成就先解释实际进度；需要备份时明确切换到另一条完整记录，不用另一项已完成任务承接当前任务的“现在完成了”。来源、核验、应用三阶段和未知停止隔离放在追问页，仍保留完整证据。

这句话是产品记忆点，不是原创技术主张。不要把“借的是设备，留下的是进度”扩写成零损失、永不中断、保证完成；保存失败和原租约到期都是真实边界。

## 3. 真正留出最后 20 秒，并把评分证据从口头清单移到备份

主稿第 5 行说讲述 4:40、余量 20 秒，但 4:40–5:00 又安排了 81 个讲述字符，实际已把余量用完。成本段约 269 个讲述字符；按每分钟 240 字的排练估算，仅说话约 67 秒，已经超过其 65 秒配额，尚未算看表和停顿。这只是文本估算，不是真人测速。全稿约 950 个讲述字符，整体并非必然超时，真正风险是局部密度与操作延迟集中。

**可替换最后一段：**

> 织算把一次临时借用接成一项完整的工作：设备主人有明确的收回边界，使用者看得见留下的进度，也拿得到最后的结果。我们希望校园里共享出去的不只是空闲时间，而是能够继续完成的工作。

结束时无需再邀请现场随机选择收回或失败条件；这属于答辩时间，另留入口即可。不要为了覆盖六项评分而在 35 秒里念全部故障名、测试数量、架构术语。一次真实事件定位加一张可复核入口卡更有效。

## 终稿前仅核对四件事

1. 主图确实包含强基线，且贡献者等待与用户重算处于同等视觉地位。
2. 主讲的 505 万步属于固定实验；现场显示的进度来自当前真实工作，两种来源明确。
3. 真人连续讲两遍，并记录各段实际结束时间；尚未完成时保留未排练状态。成本段和结语不能挤掉演示所需时间。
4. `MORNING_GUIDE.md` 的页面名称与当前 UI 对齐（当前为“最近结束”）；强基线描述统一成“固定截止前保存，先完成则直接结束”，不误说实际依赖剩余时间预测。

本轮评审没有要求继续堆功能或增加无区分力实验。当前最需要的是把已有真实证据放到最有解释力的位置，并删掉抢占主线的说明。
