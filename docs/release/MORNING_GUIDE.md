# 织算：上台前阅读手册

先理解一个问题，再操作一次完整过程：**设备主人需要收回时，系统怎样决定继续算、保存，还是停止？** 五分钟路演围绕这项选择展开。页面是操作入口，决策和证据才是主线。

## 1 我们为谁解决什么问题

校园里的空闲设备通常只有一段可借用时间。设备主人随时可能需要它，借用者又不愿丢掉已经完成的计算。织算把申请、运行、收回、保存、恢复和结束连成同一项工作，并为收回窗口安排具体动作。

只有普通用户和管理员两类账户。普通用户可以同时使用算力、共享自己的设备，不需要切换成“供应者”。管理员额外管理整个资源池、实验和验证记录。Alice、Bob、Chen 都是普通用户；本次演示由 Alice 运行，Chen 收回自己的卡，Bob 可检查跨用户隔离。这个分工不是产品角色划分。

设备库存是模拟 GPU；当前 CPU 参考程序会真实运行、写保存文件、停止和恢复。它验证执行链及结果一致性。另一套参数模型研究保存成本、进度和通知窗口的不同组合。两类证据分别解释，不能把模型结果读成真实 GPU 训练加速。

## 2 登录与进入页面

按 [README](../../README.md) 启动本机预览，再打开其列出的 CPU 入口。本轮预览惯用 CPU 端口 15253、模拟端口 15252；具体运行状态以启动输出为准。两个实例的数据和登录分别管理。

输入账户与密码，点击“登录”。正常会话会保持七天，刷新页面无需重新登录，也不需要导入身份文件。账户菜单里的“退出登录”结束会话。初始账户由本机部署生成，原预览密码文件位于 `runtime/release-preview-morning-20261115/cpu/login-accounts.txt`；重建实例后使用新生成文件。密码只由部署者查看，勿出现在投影或截图里。

要同时使用 Alice 和 Chen，请用不同浏览器或独立浏览器配置文件。一个浏览器配置文件里的多个普通窗口共用会话，不能拿来同时扮演两个人。

## 3 页面怎样使用

| 页面 | 主要用途 | 先看什么 |
|---|---|---|
| 总览 | 发现需要处理的事情，进入工作 | 收回提醒、进行中工作、最近结果 |
| 我的工作 | 按名称查找、新建工作 | 名称和状态 |
| 工作详情 | 看执行、恢复、取消、释放、下载 | 当前状态与收回进度 |
| 我的设备 | 管理自己共享的设备，主动收回 | 每张卡的实际状态与收回安排 |
| 活动记录 | 追溯发生了什么 | 事件顺序、工作链接 |
| 分配说明 | 解释为什么获得或没有获得资源 | 候选与实际提交 |
| 系统管理 | 管理员查看资源和对照记录 | 系统状态；展开“收回策略对照” |

顶部“总览 / 工作台”切换空间，侧栏选择业务页。总览保留轻量背景，工作台保持清晰。手势是额外入口，现场点击最可靠。

工作详情、我的设备、总览会每两秒自动读取状态，不会每次重新清空表单。正在借用的设备收到收回通知时，即使处于其他工作区，也能看到顶部提醒并进入相关工作。工作详情已有提醒时不重复展示同一条。

CPU 实例的倒计时来自服务端截止时间，并在两次读取之间平滑减少；连接中断或数据过旧会显示“状态待更新”。数字到零只意味着等待服务端确认，页面不能自行宣布已归还。模拟实例显示逻辑秒，现实等待不推进它。

## 4 亲手走一次

### 先启动一项有名字的工作

Alice 登录，点击“新建工作”，填写容易识别的名称，例如“现场矩阵计算”。选择实际可用的 A10、一张卡、租约 300 秒。演示保存接续时，选择“保存点恢复”和“结束后归还”。提交后直接进入工作详情。

“保存点恢复”要求有效保存点才能继续；“尽力运行”允许没有保存点时从头计算。后者才允许为了节省昂贵保存而主动舍弃少量进度。选项不只是文案差异。

若资源暂时不足，保留原工作等待。请求结果不确定时查询原工作，不再提交一项同名工作。

### Chen 主动收回

进入 Chen 的“我的设备”，展开“收回设备”，选择确实属于他的 A10。建议排练时用提前通知 15 秒、自用 15 秒，便于看清阶段。选择两张 A10 会使没有其他兼容资源时的等待更明显。

“收回方式”有两个选项：

- **尽快归还，默认**：设备主等待的权重较高。
- **尽量保留计算，主动选择**：允许在通知窗口内多等待，以争取完成或保存更多进度；归还截止不会因此延长。

点击“收回设备”并确认后，服务端检查设备归属，建立收回安排。Alice 不需要同意，也不需要点击归还。系统执行保存或停止，到期继续主动处理；CPU 进程不配合会升级停止。只有确认退出后，设备才解除占用。无法确认退出时保持隔离，不能强行把账本改成空闲。

### 看懂提醒，不抢操作

Alice 会自动看到提醒。根据实际计划，可能先继续计算、立即开始保存，或稍后才保存。优先完成的计划没有如期完成时，会转入预留的保存窗口。页面区分“继续计算”和“正在保存”，不把计划当作已经完成的事实。

保存倒计时以实际执行的停止边界为准。这可能比主人填写的提前通知时间短，因为任务还有自己的保存期限，系统也要预留停止确认时间。Chen 的收回倒计时和 Alice 的保存倒计时不必相同。

在工作详情展开“技术详情 → 收回决策记录”，能看到本次输入、各候选代价、选择理由、实际保存和停止时间。完成与恢复后，历史决策仍保留。普通用户只能看自己的工作。

### 恢复和下载

页面出现“进度已保存”后，可点击“恢复这项工作”。没有兼容设备时先等待；实际开始下一次执行才消耗恢复次数。恢复沿用原工作，原租约截止不延长。

“进度已保存”是文件已核验；“已从保存点继续”是下一次进程真的使用了它。最终点击“查看结果”或“下载结果”，检查工作完成与资源归还。若新建时选择保留租约，正常结束后仍需释放；贡献者主动收回不受借用者这个选择阻止。

## 5 决策原理，用两个直观例子理解

**例一：只算了半秒，保存却需要两秒。** 如果允许从零重启，保存并不一定划算。参数模型里，直接停止在 0.1 秒后归还，强简单基线立即保存需要 2.1 秒。多付 0.5 秒重算，省下 2 秒保存，默认偏好下综合代价从 23.8 降为 20.3。这是“不要为了保住很少的进度付出更大的保存成本”。

**例二：任务还要算很久，但主人愿意多等。** 可以先计算一小段，再保存，让归还后的剩余工作更少。代价是设备主等待更长，而且若保存耗时估错，晚保存可能来不及。这不是免费的优化，主人必须明确选择相应偏好。

系统先检查时间是否来得及，再比较：

> 归还后剩余计算 + 保存/重启开销 + 设备主等待 × 偏好权重。

“尽快归还”的权重为 1，“尽量保留计算”为 0.25。这是两种公开的产品偏好，不是从结果里拟合出的最优权重，也不是金钱价格。实际计算速度来自执行器签名进度；缺少足够新鲜的数据时退回保守保存，不能拿未来结果做预测。

停止边界取任务保存期限与“主人截止减去停止预留”中较早者；计划保存时刻还要扣除预计保存成本与报告余量。完成、保存、继续运行到某个时刻、停止，都是围绕这个边界安排的。通知提前量太短时，优先收回；要求保存成功的工作可能失败，失败必须如实保留。

详细算法及四条评审意见的对应修正，见[机制设计](../research/RECLAIM_AWARE_DESIGN.md)。

## 6 当前证据到底说明了什么

参数研究固定 14 个条件、5 种策略、2 种偏好；同一条件下比较相同输入。生产使用的规划器直接用于自适应实验，没有另写一个只在实验里表现好的版本。固定最晚保存和“能完成则完成、否则立即保存”都在对照中。

| 偏好 | 对强简单基线的全量结果 | 必须同时记住 |
|---|---|---|
| 尽快归还 | 平均代价 67.1143 → 66.7929，降低约 0.48% | 2 例更好、12 例持平；不是明显的整体性能飞跃 |
| 尽量保留计算 | 66.2411 → 67.1116，上升约 1.31% | 7 例更好、5 例持平、2 例更差；1 次晚归还 |

主表允许失败后从零重启，各策略最后都完成 14/14，但保存失败仍单独计数。要求必须保存成功的模式另列控制案例；它不能使用舍弃进度的经济性优势。模型条件不是校园负载的概率分布，不能据此声称普遍提速。

我们的闪光点是：从真实的收回冲突出发，给出可执行的选择原则，允许设备主人表达偏好，并把决策和结果保留到能逐例核对。Checkpoint 本身不是原创；本轮也没有实现风险感知放置或真实 GPU 训练适配。旧放置策略 P/B2=1.00 保留在研究历史，不用于证明新机制有效。

完整数字与不利条件见[对照结论](../research/RECLAIM_AWARE_RESULTS.md)。管理员在“系统管理 → 收回策略对照”可查看两种偏好的结果并下载原始报告和协议。“历史策略版本”表示报告所用规划器与当前代码不一致，不能把它当作当前版本的结果。

## 7 关键状态和应对

| 页面状态 | 真实含义 | 操作 |
|---|---|---|
| 最多继续计算 / 开始保存前 | 已有收回计划，保存尚未开始 | 观察自动更新 |
| 保存剩余 | 保存阶段已开始，显示实际停止边界的剩余时间 | 不需要手动归还 |
| 正在确认停止 | 已到停止阶段，仍需执行器确认 | 等待，不能宣布资源空闲 |
| 停止未确认 · 设备保持隔离 | 当前无法确认进程退出 | 管理员检查执行器；不重复释放 |
| 已收回 · 自用中 | 受影响占用已清除，仍在设备主自用窗口 | 等待自用结束 |
| 状态待更新 | 当前数据不够新鲜 | 检查连接后重新读取 |
| 进度已保存 | 保存文件已核验 | 可恢复；不等于已经接续 |
| 等待可用资源 | 暂无兼容资源 | 保留原工作，不重复新建 |
| 保存失败 / 运行超时 | 实际失败分支 | 查看原因和资源处置，不读成完成 |
| 找不到记录 | 不存在或当前账户无权读取 | 检查账户和工作，不能越权取证 |

## 8 上台前十五分钟

1. 用将要演示的电脑按 README 启动，分别登录两个普通账户和管理员，确认登录刷新、工作、设备和报告可用。
2. 做一次真实收回，不让 Alice 主动归还，观察提醒、阶段、实际停止与 Chen 的设备状态；确认自己知道每个观察位置。
3. 看一次完成后的收回决策记录；下载一个结果，确认保存与实际接续的区别。
4. 确认投影使用当前报告，数字与[五分钟稿](ROADSHOW_5MIN.md)一致。准备完整录屏作为故障备份，并保留日期、工作 ID 与真实失败分支。
5. 连续讲两遍，控制在 4 分 40 秒。台上不逐页介绍，不用测试数量替代机制，不把小幅平均收益讲成通用突破。

首次亲手排练、自动化检查、真实 CPU 流程和独立部署是不同记录。阅读手册本身不等于完成排练；最终验收是否通过，以本次冻结版本的实际记录为准。
