# 织算 上台前阅读手册

这份手册按“先理解，再亲手操作，最后准备回答问题”的顺序编排。织算服务于校园里的临时共享算力：设备可以随时被贡献者收回，使用者的工作则需要尽可能继续。先用 15 分钟读前四节，再在浏览器中亲手完成一次提交、收回和恢复。路演只讲一条完整的工作经历，不逐页介绍功能。

## 1 我们做的到底是什么

校园里一张空闲 GPU 不等于一张可以长期独占的 GPU。贡献者可能下午要做实验，使用者可能训练到一半。把空闲设备列出来只是入口；真正影响双方是否愿意使用的，是收回时会发生什么。

织算维护一套资源账本，并把一次工作的申请、执行、中断、继续和结束连在一起。贡献者可以提出收回，使用者可以看到需要处理的工作、选择继续或取消。恢复时沿用原工作，增加一次执行，原来的租约截止和恢复预算继续有效。

今天演示的设备库存是模拟的；CPU 参考程序会启动真实进程、生成真实保存点并从保存点继续。它适合验证执行接续和结果一致性。填写的资源需求用于调度账本，不能把它理解为已经启动了一项真实 CUDA 训练。

## 2 一个人可以同时使用和贡献

我们只有一个平台。普通账户可同时有“使用算力”和“贡献设备”的权限，不需要换身份才能做另一件事。拥有两种权限，不代表已经有自己的设备。没有共享设备时，页面不会假造一台卡。

管理员是额外权限：查看整个资源池、运行隔离实验、读取报告。普通用户看到自己的工作与授权数据；他人的工作和工件不能通过猜 ID 打开。登录后由服务器确定用户身份和权限。

本机试用入口是 <http://127.0.0.1:15253>，逻辑模拟入口是 <http://127.0.0.1:15252>。两个实例分别登录，数据独立。输入账户和密码后点击“登录”，会话保留七天；刷新整个页面也会保持登录。账户菜单中的“退出登录”会结束当前会话。

本机初始密码保存在 `runtime/release-preview-morning-20261115/cpu/login-accounts.txt`。部署者查看一次后，用正常登录页进入；不需要导入文件。不要在投影中打开密码文件。Alice（`alice`）、Bob（`bob`）、Chen（`chen`）都是普通用户，都可以使用算力和共享设备；本次演示安排 Alice 运行工作、Chen 收回自己已共享的设备，Bob 可用于验证用户间隔离。`admin` 是管理员账户。

## 3 如何读页面

| 页面 | 你在这里做什么 | 先看哪里 |
|---|---|---|
| 总览 | 看当前需要处理什么，进入工作 | 需要处理、进行中、最近结束 |
| 我的工作 | 新建、按名称找工作、查看结果 | 工作名称和状态 |
| 工作详情 | 恢复、取消、归还资源、下载结果 | 当前状态、可用操作、执行进度 |
| 我的设备 | 看自己的共享设备，发出收回通知 | 实际设备与“收回设备” |
| 活动记录 | 追踪工作经历，导出事件 | 发生了什么以及顺序 |
| 分配说明 | 从工作或活动进入，查看为什么分配 | 候选和实际提交结果 |
| 系统管理 | 管理员看资源池和研究记录 | 系统状态；工具默认收起 |

总览保留轻量的艺术背景，工作台使用安静的实色底。顶部“总览 / 工作台”直接切换，侧栏负责具体业务页。账户菜单内可选择页头横向手势；它是额外入口，不替代点击、键盘或手机操作。浏览器对双指手势的识别存在设备差异，现场用点击即可，别把手势作为唯一演示路径。

总览同一项工作不会同时出现在待办和进行中列表。列表是最近一页记录，不是全局统计。工作台只展示当前可操作的动作；当前执行的保存点摘要和保存点记录留在执行进度中；租约技术 ID、预算和操作回执集中在“技术详情”。这让日常使用者先处理工作，调试时仍能找到证据。

## 4 亲手走一次完整流程

### 提交一项有名字的工作

用 `alice` 登录，点“新建工作”，输入容易识别的名字，例如“明早路演计算”。选择演示资源中的 A10，一张卡，租约 300 秒。使用“保存点恢复”，结束后归还。高级设置保留默认。

点击提交后会直接打开该工作。若显示等待中，先刷新观察，不要再新建同名工作。若请求结果未确认，使用原工作的查询入口；不要把网络重试变成第二项工作。

### 用另一位用户收回设备

在独立浏览器配置文件或另一浏览器中，用 `chen` 登录，进入“我的设备”，展开“收回设备”。同一浏览器配置文件中的普通窗口共用登录状态，不适合同时演示两个账户。选择实际的 A10 设备，设置提前通知 3 秒、自用 15 秒，确认收回。演示中同时收回两张 A10 卡，可以明确展示没有兼容资源时的等待。

收回会影响正在使用这些设备的工作。回到 Alice 的工作详情刷新：先看到中断或保存状态，再看到可以恢复。Chen 以普通用户身份收回自己的设备，服务器会检查设备归属。

### 恢复原工作

点击“恢复这项工作”。资源还没回来时，保持等待；再次刷新不会消耗新的恢复次数。资源可用后才启动下一次执行。工作仍是原来的工作，原租约的截止时间不会重置。

“进度已保存”说明保存点已核验；“已从保存点继续”说明下一次执行实际使用了它。这两个状态不能互相替代。可以展开保存点记录查看报告、核验和应用的不同事实。

### 查看完成和归还

完成后点“查看结果”或“下载结果”。下载的是服务返回的原始结果文件。页面还应显示“资源已归还”。如果新建时选了保留租约，工作结束后资源可能仍占用，需要主动释放。

模拟实例的现实等待不会推进逻辑时间，需管理员在系统管理里推进模拟时钟。真实 CPU 实例会随时间运行。两种模式不要混着演示。

## 5 内部机制用一个例子说明

把一项工作想成一个有固定编号的作业。租约是使用设备的期限；任务是作业的执行安排；执行代次是第几次真正启动进程。中断后新建一个执行代次，不必新建整份作业。

每次改变资源占用都通过同一条命令处理路径。在一次事务内检查身份、版本、当前状态和预算，再一起更新账本与回执。重复请求用幂等记录识别，不能重复分卡。读页面不会另造一套资源状态。

收回后有两条必须同时照顾的线。贡献者一侧，进程停止被确认后，资源才可以重新使用；不能因为已经发出停止命令，就把仍在运行的进程当成消失。使用者一侧，保存报告要经过文件来源和内容核验，新进程实际加载后，才能算一次成功接续。停止无法确认时保留隔离；保存失败就如实失败，不用绿色状态掩盖。

租约时间和恢复预算构成边界。最初获配后开始计租约；中断等待也消耗租约；恢复不会获得新的完整期限。等待资源不扣恢复次数，实际建立新执行才计数。任务本身的失败重试和贡献者收回后的恢复分别计数。

CPU 参考程序每一步依赖上一步状态。保存文件包含进度和状态值；恢复从这个进度继续。最终结果还通过独立的矩阵计算核对，避免只拿程序自己输出的“正确”当作证明。

## 6 创新应该如何理解

Checkpoint、幂等和状态机都有已有技术。我们的展示重点是临时共享里的具体冲突：贡献者能收回，使用者已经完成的计算仍能保留，而且能解释究竟保住了多少、付出了什么成本。

这轮研究先核算实际重复的计算步骤、保存恢复开销和贡献者等待，不再把整个被中断执行都算成浪费。接续和从零重启使用同一计算程序及中断条件，并保留零进度和保存失败的情况。本轮已实际比较固定截止前保存基线：在通知截止前固定提前量保存，此前完成则直接交付。当前成果主要是系统设计和工程可信度，尚未证明新的调度算法优于强简单基线。具体数字见[损失核算](../research/FINAL_LOSS_ACCOUNTING.md)及[五分钟讲稿](ROADSHOW_5MIN.md)。早先 P/B2=1.00 仍是未获得策略提升的结果。

要区分三个层次：产品机制已运行；特定参考负载的成本已实测；比强简单策略更好的通用调度算法是否成立。台上可以有力地展示前两层，第三层要按本轮实测结论回答。

## 7 遇到问题时如何判断

| 现象 | 意味着什么 | 操作 |
|---|---|---|
| 等待可用资源 | 目前没有兼容空闲资源 | 保留原工作，刷新；必要时查看分配说明 |
| 资源已就绪，准备启动 | 已拿到资源，但尚未创建任务 | 刷新；若出现重试任务创建，使用该操作 |
| 资源正在收回 | 租约处于收回通知阶段 | 等待保存和停止；不能在该租约新建任务 |
| 进度已保存 | 文件已核验，尚不等于新进程应用 | 恢复并观察下一次执行 |
| 暂未确认结果 | 连接没有给出确定结果 | 先查询原工作，不重复提交 |
| 请重新登录 | 会话已过期或失效 | 用当前实例的账户和密码登录 |
| 找不到记录 | 记录不存在或此账户不能访问 | 核对账户和工作 ID；不要切管理员绕过隔离演示 |
| 运行超时 | 触发了运行上限 | 查看失败原因及资源归还；不要将其包装为完成 |

## 8 上台前的十五分钟

1. 用将要演示的电脑打开本机 CPU 实例。在三个独立浏览器配置文件或不同浏览器中，分别登录 Alice、Chen、Admin，确认工作、设备和管理页面可打开；投影不显示密码。
2. 亲手走一次完整收回与恢复，记住“原工作不变、新执行增加、最终资源归还”这三个观察位置。
3. 核对五分钟稿中的数字与本轮实验结论一致；准备完成截图和结果文件作为现场连接故障时的备份，明确说明它们是已录制记录。
4. 读一遍困难问题回答，再连续讲两遍，用计时器控制在 4 分 40 秒左右，留出 20 秒操作和停顿空间。

原比赛候选的标签与验收记录保留；本手册已同步当前账户登录与用户称呼修订。开发与本机浏览器验证、研究实测、第三方真人复现是不同证据；明天自己的练习要实际做，不能拿自动化记录当作已经排练过。
