# 自适应收回机制验收记录

2026-11-15，分支 `release/final-20261115`。本轮在已合入 B 页面、账户登录和普通用户身份统一的基础上，增加面向贡献者收回权的自适应计算管理。本文记录本轮实际验证范围；旧候选标签及其验收原件不改写。

## 四个问题的修改

| 原问题 | 本轮改变 | 可检查的位置 |
|---|---|---|
| 流程完整，但缺少不同于固定流程的判断 | 收回期限、任务进度、保存与停止成本共同决定完成、立即保存、延后保存或停止 | `policies/reclaim.py`、工作详情的收回决策记录 |
| 发现等待与计算损失的矛盾，却没有决策机制 | 先筛选时间与恢复约束，再比较剩余计算、保存重启开销和贡献者等待；默认尽快归还 | 设备收回表单、候选动作及成本审计 |
| 将成熟的保存点与恢复能力当作创新 | 创新叙述改为贡献者收回权驱动的运行管理；保存与恢复作为实现基础 | 机制说明、五分钟路演稿 |
| 路演以功能浏览为主 | 改为收回冲突、四选一决策、成对证据、真实运行、边界与价值 | `ROADSHOW_5MIN.md`、可打印 PDF |

## 实际浏览器与 CPU

隔离目录 `runtime/recall-live-20261115`，CPU 页面端口 15275。使用两个独立浏览器会话登录普通用户 Alice、Chen，再由 Admin 查看研究报告。真实 CPU 进程执行，GPU 库存模拟；本次流程验证使用有节奏的参考程序，不作为性能测量。

- 正常任务由设备所有者在页面发起收回；系统选择延后保存，提醒与倒计时自动更新。保存截止和设备归还截止分别显示、分别执行。
- CPU 保存点实际产生并核验，进程停止后解除占用。所有者看到已收回；设备仍遵守已公告的自用窗口。
- 使用者不进行任何操作，冻结的测试进程仍在停止升级后退出，资源确认归还。保存未完成的严格接续任务显示失败，没有伪造保存成功。
- 正常任务沿原工作恢复，下一次执行实际读取保存点并完成，资源释放。
- 收回决定、保存核验及停止确认时间在结束后仍可查询；另一普通用户读取该工作审计得到 404。
- 管理页显示当前决策器对应的对照报告；浏览器下载报告、协议与仓库原件逐字节相同。
- 两个普通用户及管理员操作未产生页面脚本异常。

原件：[浏览器回执](../../evidence/reclaim-live-20261115/browser-receipt.json)、[决策审计](../../evidence/reclaim-live-20261115/decision-audit.json)、[恢复完成记录](../../evidence/reclaim-live-20261115/resumed-completed.json)。同目录有倒计时、归还、完成和报告截图。首次自动操作脚本因重复点击已展开区域而失败，原日志保留；修正定位后重新完成上述流程。

## 对照结论与版本边界

14 个冻结模型条件 × 5 策略 × 2 偏好，另有必须保存的控制条件。它们是参数化执行模型，不是真实 GPU 样本。所有策略取得相同的因果输入和安全余量。

相对“能完成则完成，否则立即保存”的强简单基线：默认尽快归还平均双边成本降低约 0.48%，2 胜、12 平、0 负；尽量保留计算平均成本升高约 1.31%，7 胜、5 平、2 负。保存与停止估算不足的失败和超期全部保留。完整结果见 [对照报告](../research/RECLAIM_AWARE_RESULTS.md)。

第一版恢复语义、第二版资源重用时钟及保存边界的修正过程和原结果均已归档。最终报告摘要 `33588804008f10dca250d63304c87d8f26b5461d5e04ddf77df424274f9eb14b`，协议摘要 `fe9f06f26cf2caf178442c4aef798f9fc65f073e5d253dba0e511d19e9d28c24`。页面会核对报告与当前决策器，版本不符显示历史结果。

真正落地的是按收回权与实际代价选择动作；现有证据不支持普遍性能优势、任意停止耗时下绝不超期或真实 GPU 训练加速。原 P/B2=1.00、规模与延迟目标未达、另一位真人干净部署未完成等记录保留。操作系统未确认退出时继续隔离资源，不能为了显示按时归还而提前解除占用。

## 复现入口

从仓库根目录启动独立会话，避免覆盖正在试用的实例：

```bash
uv run python scripts/cp2_joint_session.py start --runtime runtime/recall-live-20261115 --logical-api-port 18274 --logical-web-port 15274 --cpu-api-port 18275 --cpu-web-port 15275
node scripts/reclaim_live_browser.mjs
node scripts/reclaim_report_browser.mjs
```

两个浏览器脚本需要 Playwright Core 和本机 Google Chrome，按顺序执行；第二个脚本继续第一个脚本的工作。可用 `PLAYWRIGHT_MODULE` 指定已安装的模块入口。账户密码仅从隔离目录读取，不写入回执；冻结进程操作只允许命令路径匹配该隔离实例的 CPU worker。新的复现会更新该证据目录，应先保留要比较的原件。

模型检查与重算入口见对照报告；重算不改变运营实例。当前试用入口、登录方式和演示步骤见 [上台前阅读手册](MORNING_GUIDE.md)。
