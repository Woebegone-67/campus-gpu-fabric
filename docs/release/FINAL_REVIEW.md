## 重点源码复核

- `common.tsx`：未知结果保留“暂未确认”，不把超时当失败已撤销；请求中 ref 阻止重复点击。刷新失败仍显示旧数据时明确标出旧记录与失败，避免假装新状态。原始错误/请求标识仍可展开查看。
- `Continuity.tsx`：可操作性来自服务端 legal actions；查询加载或失败时禁用操作。刷新后按查询时间重建动作组件，因此未知结果不会靠盲重试恢复按钮。技术详情保留完整回执、租约、代次及原始记录。
- `Run.tsx`：登记固定工作 ID 和输入后重试；结果不明时要求先查原工作；命名校验与后台身份分离。新建默认为结束归还，模拟/CPU 的执行模式来自服务端，不根据文案编造执行能力。
- `Settlement.tsx`：`pending_terminal` 的停止状态优先；工作结束与资源归还独立判断。`Job timeout` 真实错误能显示为运行超时，且无伪造成功结果。

本段是只读审查结论，不是额外浏览器执行证明。未发现需要为本轮收尾再启动架构修改的阻断。

## 数字与路演裁决

中期冷启动重复 505 万步，接续重复 5 万步；晚期为 905 万步与 5 万步。实际少执行分别为 500 万和 900 万步，不能把保存总步数直接当净节省。固定截止结算臂中期重复 0 步，但比立即保存多占通知期约 538ms；这是真实贡献者等待成本，不是无成本优势。

完整分母为保存接续 3/4、冷启动 4/4、固定截止结算 4/4。第三臂实际是一律用到通知截止前 100ms、此前完成则结束，并非剩余时间预测驱动；故障场景未走保存分支，不能称抗保存故障。报告已明确原 JSON 的预测 scope 是旧诊断说明，原件保留。

当前五分钟稿正确地把价值放在“敢借、敢跑”的可执行承诺和可核算接续。最容易被评委追问的缺口仍是新机制相对强基线的额外贡献、规模成本、真人复现；不能以页面简化或本轮损失对照宣告这些问题已解决。脚本已经写好与现场五分钟能稳定完成是两件事。
