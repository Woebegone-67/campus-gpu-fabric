# 织算 Campus Fabric：CP0 产品交接

产品承诺：资源归属可核对、工作身份不中断、决定有当时证据、效果能复验。终态与量化目标只以 `docs/blueprint/01`、`03` 为准；本页不降低目标，也不表示已有实现。

| 角色/工作区 | 必须做成的动作 | 验收所见 |
|---|---|---|
| 研究者·运行工作台 | 创建工作、续租、取消、恢复 | allocation成功而job失败时保留租约ID，提供重试原租约/释放，不重复借卡 |
| 贡献者·资源与贡献 | 登记、开放、收回自己的资源 | 受权 `/x/v1/*` 写扩展与真实归还回执；浏览器无X-Test-Key |
| 研究者·任务连续性 | 看保存、attempt、预算并领取结算 | 报告/核验/接续分列；成功或失败均显示租约最终去向 |
| 用户·决策解释 | 理解等待、选择和下一条件 | 同次快照候选及提交结果；搜索截断不得称全池不可行；估计标为条件化 |
| 管理员·事件与实验 | 隔离回放、配对与消融 | 独立run身份、原始输入/结果/失败可下载，未来数据不能流入在线策略 |
| 管理员·系统验收 | 看版本、已测/待测及失败 | 只展示实际执行记录；脚本存在不能显示MET |

三条贯穿验收的故事：研究者提交→结果/失败→租约结算；贡献者收回→保存/停止→等待/恢复→同一工作结算；管理员定位决定→隔离重放→换输入比较得失。自动归还需用户明确选择，由服务端持久工作流继续执行，关闭页面不能丢失。

B实现 TypeScript / React / Vite，Node 22；后端 Python 3.12 / uv / FastAPI。1440×900主要流程无横向滚动；每屏一个主要任务；表格、时间线、空态、加载、错误和部分成功统一。事实与预测、逻辑时间与墙钟、模拟与CPU实测有稳定文字标签；关键状态不能只用颜色。

策略起点为B0 FIFO/first-fit、B1公平准入/best-fit、B2兼容稀缺性放置；CP0冻结接口，验证前冻结排序键及同分规则。主策略P可替换，失败与负结果保留；机会损失公式的零信号反例必须运行，不能把已知失效候选直接宣传为主成果。五类×五seed、主指标、完成数和个体损害口径引用蓝图03，不另造分母。

CP0验收：六区都有对象、真实操作依赖、空/失败/部分成功设计；A写回执与B读投影形成唯一事实链。CP1才验正常旅程，CP2验动态旅程，CP3验配对与CPU实际恢复。
